# 원본 가져오기와 설정

[English](acquisition-workflow.en.md) · [사용 가이드](user-guide.ko.md) · [설치](alpha-installation.md)

**0.4.0 Alpha**의 일반 가져오기는 한 경로입니다. 앱이 선택한 원본을 고정하고
이미지와 구조를 준비하며 받은 자료를 자동 저장합니다. 수집 방식이나 읽기 순서를
고를 필요가 없습니다. 원본 디자인은 수정하지 않습니다.

## 원본 추가부터 검토까지

1. 작업 공간을 열고 Figma에서 허용된 컨테이너 하나를 선택합니다.
2. **원본 추가**를 누르고 이름·경계·예산을 확인합니다. 이 단계에서는 이미지나
   전체 구조를 읽지 않습니다. 총 노드 수와 시간은 아직 알 수 없습니다.
3. **가져오기 시작**을 누릅니다. 이미지를 준비한 뒤 구조를 최대 500개·1MB씩
   읽고 저장합니다. Figma의 무거운 읽기는 동시에 실행하지 않습니다.
4. 받은 이미지는 자동으로 같은 작업 공간에 나타납니다. 구조가 완성되기 전에도
   영역과 이름을 제안 상태로 저장할 수 있습니다. 이미지 실패 시에는 정상 구조를 보존합니다.
5. 구조가 완성되면 같은 이미지 초안에 자동 연결합니다. 작성 중인 영역이 있다면
   먼저 **영역 저장**을 누르세요. 원본이 준비되면 영역을 저장하고 연결된 노드를
   확인한 뒤 **원본 확인 → 영역 승인**을 진행합니다.
6. 완료한 가져오기는 **원본 준비 완료**로 표시됩니다. 자세한 수치와 이미지는
   **가져오기 세부 정보**에서 볼 수 있습니다. 승인한 영역의 **명세 연결**에서
   요구사항을 연결하고, **전달하기**에서 승인 결과를 확인하세요.

이미지와 구조는 별도 시점의 관찰입니다. 가져오는 동안 원본을 편집하지 말고
결과를 비교하세요. 구조를 완전히 읽었다고 겹친 레이어의 의미까지 확정되는 것은 아닙니다.

## 설정에서 조정할 수 있는 항목

상단 **설정**에서 값을 바꾸고 **설정 저장**을 누릅니다. 컴퓨터의 로컬 데이터에
저장되며 새 가져오기·재개부터 적용됩니다. **이미지 품질**과 **원본 가져오기 한도**를
먼저 조정하고, 대기 시간을 바꾸려면 **연결 대기 시간**을 펼치세요.
이미 받은 이미지와 승인한 원본은 유지됩니다.

| 항목 | 기본값 | 설정 범위 |
| --- | --- | --- |
| 이미지 배율 | 2배 | 0.25–4배 |
| 이미지 긴 변 | 4,096px | 256–8,192px |
| 이미지 용량 | 8MB | 0.1–9MB |
| 이미지 대기 | 55초 | 1–300초 |
| 원본 노드 수 | 200,000개 | 1–1,000,000개 |
| 원본 용량 | 64MB | 1–128MB |
| 자동 일시정지까지 읽기 시간 | 300초 | 1–1,800초 |
| 구조 응답 대기 | 20초 | 1–120초 |
| 일시정지 연결 유지 | 10분 | 1–30분 |

기본 미리보기는 이전보다 가로·세로 각각 두 배입니다. 예를 들어 800×600으로
가져오던 화면은 1,600×1,200, 긴 변 2,048px로 축소하던 큰 화면은 최대 4,096px로
가져옵니다. 픽셀 수는 약 네 배가 됩니다. 배율과 긴 변 한도가 함께 적용됩니다.
큰 표의 작은 글씨는 원문으로 확인하세요.

한도를 높이면 Figma 메모리·시간·디스크 사용이 늘어날 수 있습니다. 전송 묶음 크기,
자료 검증과 승인 규칙, 파일 형식 등의 보호 한도는 설정과 별도로 유지합니다.
Figma 내부의 자식 배열 생성과 이미지 렌더링은 앱의 응답 예산으로 최대 메모리를
보장할 수 없습니다.

## 한도에 도달했을 때

- **노드·용량·실행 시간 한도는 일시정지 사유**입니다. 저장한 부분을 지우거나
  작은 범위의 성공으로 바꾸지 않습니다. **설정 → 한도 조정 → 계속**으로 진행합니다.
- 같은 연결과 원본이 유효하면 다음 미수신 노드·묶음부터 읽습니다. 이미지도 다시
  요청하지 않습니다. 용량은 다음 묶음의 최대 크기를 남겨 두고 조금 일찍 멈출 수 있습니다.
- 일시정지는 현재 이미지 내보내기나 묶음 저장이 끝난 뒤 적용됩니다. 실행 시간
  예산은 즉시 중단이나 전체 작업 완료 시간을 보장하지 않습니다.
- 연결 유지 시간 변경은 다음 묶음을 읽을 때 적용됩니다. 이미 만료된 읽기 위치를
  새 설정으로 복구할 수는 없습니다.

**5,000개는 일반 가져오기의 실패 기준이 아닙니다.** 이전 작은 캡처 형식의
5,000개 기본값과 10,000개 저장 상한은 기존 파일·API 호환에 남아 있으며,
일반 화면의 새 가져오기는 그 경로를 사용하지 않습니다.

## 연결 변경과 오류

| 상황 | 다음 행동 |
| --- | --- |
| 같은 연결에서 일시정지 | 원본을 바꾸지 않고 설정한 유지 시간 안에 **계속** |
| 잠시 응답 지연·Figma가 바쁨 | 원인을 확인하고 같은 유효한 연결에서 **계속** |
| 재연결·앱 재시작 | **계속**에서 비용을 확인한 뒤 같은 원본을 다시 검사. 기존 이미지·자료·승인은 보존 |
| 원본 삭제·다른 파일이나 페이지 | 새 읽기는 중단하고 저장 자료는 유지. 허용된 원본으로 돌아가거나 유효한 백업 복원 |
| 이미지 실패 | 경고 확인. 완전한 구조는 이미지 없이 사용 가능 |
| 구조 미완료 | 받은 노드·원문 조회 가능. 끝까지 읽힌 부분은 별도 검토하고 덜 읽힌 컨테이너는 그 부분만 준비 |
| 자료 손상·다른 출처 | 정상 자료로 바꾸거나 백업 복구. 같은 요청 반복으로 완료 처리하지 않음 |

재연결 후에는 **저장된 노드도 Figma에서 다시 읽습니다**. 같은 내용은 짧은 확인
응답으로 반복 전송을 줄이지만 Figma 읽기 비용은 남습니다. 이름과 크기가 같아도
원문·하위 구조가 같다고 볼 수 없기 때문입니다. 이전 관찰·승인은 보존하고, 유지한
이미지를 현재 이미지로 다시 확인했다고 표시하지 않습니다. 고정된 한 시점의
Figma 버전을 보장하지 않습니다.

## 필요한 부분부터 작업

**받은 원본 자료**를 열어 저장된 노드를 검색하고 **원문 읽기**를 선택합니다. 이 조회에는 Figma
연결이 필요하지 않습니다. 아직 읽지 않은 원문과 빈 원문을 구분합니다. 끝까지 읽힌
부분은 **이 부분 검토**로 큰 이미지 위에서 별도 검토합니다. 같은 이미지에서 현재
선택한, 저장된 제안 영역은 복사하며 기존 승인은 바꾸지 않습니다.

덜 읽힌 컨테이너는 **이 부분 준비**로 그 하위 구조만 가져옵니다. 필요한 부분을
읽을 때 그 안의 원문도 함께 저장하며, 이후 원문 조회는 로컬 저장 자료를 사용합니다. 기존 읽기
위치를 놓아야 한다면 원래 전체 작업을 계속할 때 다시 검사가 필요함을 설명하고
확인받습니다. 원래 전체 요청은 미완료로 남습니다. 선택한 부분도 도중에 멈추면
그 아래의 **받은 원본 자료**를 열 수 있습니다. **계속**은 이 부분부터 이어 읽습니다.

부분 검토는 바깥 형제나 겹친 레이어까지 확인한 결과가 아닙니다. 표시된 원본 범위보다
큰 영역은 승인할 수 없습니다. 여러 분기에 걸친 구성요소라면 충분히 넓은 원본을
확보하세요. 원본 확인과 의미 승인은 사람이 각각 수행합니다.

## 오류 기록 확인

오류가 나타난 작업과 시간을 기록하세요. 메시지의 **오류 세부 정보**에 진단 번호가
있으면 함께 확인합니다. **브리지 → 진단 로그 폴더 보기**에서 요청 경로·작업 종류·
소요 시간·오류 코드·검증 이유를 확인할 수 있습니다. 웹뷰 오류와 콘솔 경고도
이 폴더에 기록됩니다. 원본 문구·이미지·토큰은 저장하지 않습니다.

기본 위치는 `~/.figma-semantic-bridge/logs`입니다. 로그는 용량과 보관 정책에 따라
순환하므로 오류 발생 직후의 기록을 확인하세요. 웹뷰를 직접 살펴보려면
**브리지 → 웹 검사 활성화**를 사용합니다. 자세한 로컬 확인 방법은
[진단 안내](local-diagnostics.md)을 참고하세요.

## 자료 조회·정리·전달

완전한 원본의 노드 목록과 원문은 검토 화면에서 필요한 만큼 읽습니다. 캔버스에
불러온 경계 수와 전체 노드 수는 다릅니다. 에이전트의 특정 ID·바로 아래 목록 읽기는
별도 조사 결과이며 전체 범위가 완성됐다는 뜻이 아닙니다.

**저장된 가져오기 기록**에서 쓰지 않는 기록을 정리할 수 있습니다. 작업 공간에서
사용하는 원본·이미지는 보호됩니다. 기록 삭제는 백업이 아니며 해당 중단 자료도
지워집니다. 다른 작업 공간의 기록은 그 공간에서 정리하세요.

이미지 가져오기 캐시는 최대 12개·96MB, 구조 수집 캐시는 최대 12개·512MB입니다.
원본 파일 전달은 완전한 구조와 있으면 이미지를 최대 80MB NDJSON으로 옮깁니다.
한도를 높여 80MB보다 커진 자료는 원본 파일 전달이 막힐 수 있으므로 검토 결과 전달과
전체 백업을 구분하세요. 이전 작은 캡처 묶음은 최대 두 개·15MB이며 주석·승인을
전달하지 않습니다. [사용 가이드](user-guide.ko.md)와 [백업 안내](upgrade-guide.md)를 참고하세요.
