# 이미지와 구조를 나누어 가져오기 — 개발 버전

[English](acquisition-workflow.en.md) · [기존 사용자 가이드](user-guide.ko.md) · [설계와 남은 범위](adr/0006-image-first-lazy-acquisition.md)

이 흐름은 2026-10-26까지 작업 트리에 구현됐습니다. 이미 배포한 **0.1.1 앱과 플러그인에는
포함되지 않습니다.** 새 서버·웹·플러그인을 같은 소스로 빌드해 함께 사용해야 합니다.
기존 알파의 보안·데이터 취급 주의사항도 그대로 적용됩니다.

목표는 요청한 작업을 빠뜨리지 않는 것입니다. 이미지가 보인다는 사실과 구조를
완전히 읽었다는 사실을 구분합니다. 필요한 자료를 나중에 읽을 수는 있지만,
읽지 않은 자료를 없는 것으로 간주하거나 완료로 표시하지 않습니다.

## 권장 순서

1. 작업 공간을 열고 미저장 편집을 저장합니다. 연결된 Figma에서 허용된 컨테이너 하나를
   선택한 뒤 **Figma 선택 영역 캡처(Capture Figma selection)**를 누릅니다.
   이 단계에서는 선택의 식별자와 경계만 확인하며, 하위 구조 순회나 이미지 렌더링은 하지 않습니다.
2. 표시된 원본 이름·종류·경계를 확인하고 가져올 순서를 고릅니다. 노드 수와 소요 시간은
   아직 모릅니다. 화면 크기만으로 정밀한 시간이나 메모리 추정치를 만들지 않습니다.
3. 비용과 제한 안내를 읽고 **가져오기 시작(Start acquisition)**을 누릅니다.
   현재 작업은 이때 선택한 원본에 고정됩니다. 이후 Figma 선택을 다른 곳으로 옮겨도
   작업의 대상이 자동으로 바뀌지는 않습니다.
4. 단계, 경과 시간, 실제 읽은 노드 수·바이트를 확인합니다. 전체 분량을 모르므로
   완료 퍼센트를 표시하지 않습니다. 받은 이미지는 **개요 이미지 크게 보기(Enlarge overview)**로
   확인할 수 있고, 확대 때문에 Figma에 새 렌더링을 요청하지 않습니다.
5. 이미지만 준비됐다면 **개요 이미지를 시각 초안으로 사용(Use overview as visual draft)**을
   눌러 제안 상태의 영역을 그리거나, 기존 작은 캡처 경로의 **원본 구조 읽기(Load source structure)**를
   선택합니다. 구조를 읽을 때 PNG는 재사용합니다. 시각 초안은 완전한 수집을 명시적으로
   연결하기 전까지 원본 매칭·확인·승인을 할 수 없습니다.
6. 작은 캡처는 필요한 단계가 완료된 뒤 **완료된 캡처 저장(Save complete capture)**을
   누릅니다. 큰 원본은 **원본 구조 수집(Raw source collection)**을 마친 뒤 일치하는
   시각 초안에 연결하거나 이미지 없는 원본 범위로 추가합니다. 이미지와 구조는 어느
   경우에도 서로 다른 시점의 관찰입니다.

## 어떤 순서를 고를까

| 선택 | 적합한 경우 | 결과 |
| --- | --- | --- |
| 개요 이미지 → 구조 | 화면을 먼저 확인하고 같은 범위의 구조도 필요함 | 이미지가 도착한 뒤 구조 읽기가 계속됨 |
| 구조 → 개요 이미지 | 원문과 노드 정보 확인이 먼저 필요함 | 구조를 먼저 읽고 이미지를 요청함 |
| 개요 이미지만 | 먼저 화면을 보고 구조 읽기 여부를 결정함 | 이미지 관찰만 저장됨. 나중에 구조를 추가할 수 있음 |
| 구조만 | 이미지 없이도 원문과 구조로 작업할 수 있음 | PNG를 요청하지 않음. 완전한 구조는 저장 가능 |

한 단계가 실패해도 성공한 다른 단계는 남습니다. **개요 이미지 다시 시도(Retry overview)** 또는
**구조를 처음부터 다시 읽기(Retry structure from the beginning)**는 해당 단계만 다시 실행합니다.
구조 재시도는 이어 읽기가 아닙니다. 같은 제한 때문에 반복해서 잘린다면 같은 재시도를
계속해도 전체 범위가 완성되지 않습니다.

**가져오기 중단(Stop acquisition)**은 대기와 협력적으로 중단 가능한 읽기를 멈춥니다.
이미 시작된 Figma 내부 렌더링을 강제로 끝내지는 못합니다. 앱이 중단됐다고 표시해도
플러그인은 내부 작업이 끝날 때까지 잠시 바쁠 수 있습니다. 새로고침이나 창 닫기는
중단 버튼의 대체 수단이 아닙니다. 시작된 작업은 서버에 보존됩니다.

**최근 가져오기 작업(Recent acquisition jobs)**에서 이전 결과를 다시 확인합니다.
**가져오기 기록 삭제(Remove acquisition record)**는 해당 작업의 캐시를 삭제합니다.
이미 작업 공간에 저장한 캡처와 주석은 삭제하지 않습니다. 캐시는 서버 전체에서 최대
12개 작업이며, 다른 작업 공간의 캐시는 해당 작업 공간에서 정리할 수 있습니다.

## 큰 구조를 묶음으로 수집하고 필요한 부분만 조회하기

작업 공간의 **원본 구조 수집** 패널을 사용합니다. 이 결과는 승인 전 원자료이며,
기존 캡처·영역 주석·승인된 코딩 맥락과 별도로 보관됩니다.

1. Figma에서 수집할 컨테이너를 선택하고 준비 버튼을 누릅니다. 원본 범위와
   20만 노드·64 MB 한도, Figma 내부 비용의 불확실성을 읽은 뒤 시작합니다.
2. 최대 500개 노드·1 MB씩 읽고 저장합니다. 이미 저장한 묶음은 재개할 때 다시 읽지 않습니다.
   전체 개수를 미리 세지 않으므로 진행률 대신 실제 노드 수·바이트·경과 시간이 나옵니다.
3. 일시정지는 현재 묶음을 저장한 뒤 적용됩니다. 한 번의 실행이 5분을 넘으면
   묶음 사이에서 자동으로 일시정지합니다. 같은 세션에서 재개할 수 있지만,
   유휴 10분이 지나거나 원본·페이지·연결이 바뀌면 새 수집이 필요합니다.
4. 전체 구조의 누락·중복·부모 관계 검증이 끝나면 노드 목록을 페이지별로 봅니다.
   원문은 해당 노드에서 요청할 때만 표시됩니다. 긴 원문은 계속 읽기를 사용합니다.
   MCP도 특정 ID, 직접 자식 목록, 원문 일부를 따로 요청할 수 있습니다.
5. 기록은 새로고침 후에도 남습니다. 앱 재시작은 진행 중인 Figma 순회를 이어 주지 않습니다.
   미완료 자료는 조회·승인 가능한 완성본으로 바뀌지 않습니다.

이 경로는 **Figma에서 선택한 하위 트리 전체를 먼저 수집하고, 로컬 저장소에서 필요한
부분만 읽는 방식**입니다. 알려진 ID나 특정 가지에 필요한 자료만 처음부터 읽으려면
**선택적 원본 조사(Selective source inspection)**를 사용합니다. ID 최대 100개의
메타데이터 또는 요청한 원문, 부모 바로 아래 자식의 묶음별 목록, 선택한 하위 컨테이너의
완전한 가지 수집을 지원합니다. ID 조회는 해당 ID·필드만, 직접 자식 목록은 자손을
제외한 바로 아래 자식만 입증합니다. 가지 수집도 선택한 가지 아래에서만 완전합니다.
응답을 나눠도 Figma의 폭이 큰 부모에서 `children` 배열 전체가 먼저 할당될 수 있습니다.

수집이 완료되면 **수집을 원본 범위로 추가(Add collection as source scope)**하여
이미지를 만들어내지 않고 문서 경계 위에 영역을 그리거나, 파일·페이지·루트·경계가
일치하는 **현재 시각 초안에 연결(Attach to current visual draft)**할 수 있습니다.
시각 초안의 이미지와 제안 영역은 유지됩니다. 편집기는 구조 메타데이터를 페이지별로
읽고, 선택한 출처·TEXT 원문만 요청하며, 전체 노드 수와 화면에 불러온 경계 수를
구분합니다. 출처 집합을 저장하고 사람이 **출처 확인(Confirm sources)**을 누른 뒤
의미를 검토하세요. 이미지만으로는 승인할 수 없고, 수집에 연결된 주석은 항상 사람의
명시적인 출처 확인이 필요합니다.

**원본 근거 파일 전달(Source evidence transfer)**은 완전한 수집 범위 하나를 최대
80MB NDJSON 파일로 내보냅니다. 원문과, 있으면 개요 이미지가 포함됩니다. 가져오기는
체크섬·종료 표시·전체 수집 범위를 검증한 뒤 현재 작업공간에 검토 전 새 범위를
추가합니다. 주석·명세·승인은 전달하지 않습니다. 작은 캡처용 Capture transfer와
별도입니다. 민감한 자료일 수 있으므로 허가된 경로에서만 전달하세요. 기존 작은
Snapshot 경로에는 아래 제한이 계속 적용됩니다.

수집 기록은 서버 전체 최대 12개·256 MB입니다. 작업이 막혔을 때 같은 요청을 반복하지
말고 오류를 확인하세요. 한도 초과는 미완료이며, 타임아웃·바쁨은 수동 재개를 기다립니다.
커서 해제에 실패하면 기록을 유지하므로 제거를 다시 시도하거나 플러그인을 다시 연결합니다.

## 기존 캡처의 제한과 완료의 의미

- UI 구조 읽기는 최대 5,000노드·메타데이터 2 MB·협력적 순회 5초입니다.
  제한에 도달하면 **미완료**이며 완료 캡처로 저장하거나 새 승인을 할 수 없습니다.
- 개요 PNG는 긴 변 최대 2,048px·8 MB입니다. 큰 표의 작은 글씨를 읽기에 충분하지 않을 수 있습니다.
  이미지 요청은 별도 시간 예산을 사용하지만, Figma의 실제 렌더링 비용을 미리 보장하지는 않습니다.
- 이미지와 구조는 서로 다른 시점의 관찰입니다. 같은 위치·이름이 유지돼도 내부 내용이
  같은 버전이라는 보장은 없습니다. 획득 중에는 원본 편집을 피하고 결과를 직접 비교하세요.
- 이미지 단독 결과는 제안 상태의 영역을 그리는 시각 초안이 될 수 있습니다. 완전한
  수집을 일치하는 원본에 연결하고 사람이 출처 집합을 확인하기 전까지 매칭·확인·승인은
  잠깁니다.
- Section의 이미지는 지원하지 않습니다. 구조만 선택하거나, 이미지가 필요한 별도 작업으로
  내부 Frame을 명시적으로 선택하세요. 범위를 줄이는 것은 원래 전체 작업의 완료가 아닙니다.
- 완전한 수집은 가짜 인라인 Snapshot 없이 편집기 범위가 될 수 있습니다. 기존 Capture
  transfer는 이를 담지 않으며 Source evidence transfer를 사용합니다. 수집 완료는 선택한
  하위 트리의 완전성만 뜻하고, 열지 않은 형제 가지나 단일 불변 Figma 버전은 증명하지
  않습니다. 실제 105,837노드 원본의 native 검증은 아직 없습니다.

최신 검증은 [수집 기반 편집 검증](evaluation/collection-backed-workflow.md)과
[이전 획득 기준 기록](evaluation/independent-acquisition.md)을 확인하세요.
합성 브라우저 검사를 실제 Figma 대형 프레임 성능 검증으로 해석하면 안 됩니다.
