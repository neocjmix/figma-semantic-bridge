# Figma Semantic Bridge 0.3.0 Alpha 설치

[English](alpha-installation.en.md) · [사용 가이드](user-guide.ko.md) · [업데이트·백업](upgrade-guide.md)

앱을 설치하고 Figma 플러그인을 연결한 뒤 MCP를 등록합니다. 앱에는 실행 환경과
미리 빌드된 플러그인이 포함되어 있어 Node.js·npm이나 소스 체크아웃이 필요 없습니다.
이전 버전 사용자는 먼저 [업데이트 가이드](upgrade-guide.md)를 따르세요.
앱과 플러그인은 같은 릴리즈를 사용해야 합니다.

## 1. 환경과 배포 파일 확인

- Apple Silicon Mac이 필요합니다. macOS 13 이상을 빌드 대상으로 하며,
  macOS 26.6.2에서 실행했습니다. 가장 낮은 대상 OS의 실행은 별도 확인되지 않았습니다.
- 새 원본을 읽으려면 Figma Desktop과 해당 파일의 읽기·내보내기 권한이 필요합니다.
  데모나 전달받은 자료 검토에는 Figma가 필요하지 않습니다.
- 로컬 개발 플러그인과 공증되지 않은 알파 앱을 실행할 수 있는 조직 정책이 필요합니다.
  다른 소유자의 보기 전용 파일에 Dev 전용 계정으로 접근하는 조합은 아직 별도
  검증이 남아 있습니다. 설치를 통과시키기 위해 편집 권한이나 소유권을 바꾸지 않습니다.

[Releases](https://github.com/neocjmix/figma-semantic-bridge/releases)에서 같은 버전의
파일을 받습니다. 선택한 릴리즈와 파일명이 **0.3.0**인지 확인하세요.

| 파일 | 용도 |
| --- | --- |
| `figma-semantic-bridge-0.3.0-macos-arm64.dmg` | Applications에 앱 설치 |
| `figma-semantic-bridge-0.3.0-macos-arm64.zip` | 앱 ZIP 배포본 |
| `figma-semantic-bridge-plugin-0.3.0.zip` | 별도 플러그인 배포본. 앱에도 같은 플러그인이 포함됨 |
| `SHA256SUMS`, 각 파일의 `.sha256` | 다운로드한 파일과 릴리즈 체크섬 비교 |
| 설치·사용 가이드 | 이 안내의 오프라인 사본 |

예를 들어 다운로드한 DMG에 `shasum -a 256`을 실행하고, `SHA256SUMS`의 같은
파일명 항목과 비교합니다. 체크섬은 바이트 변경을 확인하는 수단이며, 모르는
배포자를 신뢰해도 된다는 뜻이나 독립적인 서명은 아닙니다. 이 알파는 임시 서명을
사용하며 Developer ID 공증을 받지 않았습니다.

## 2. 앱 설치와 첫 실행

1. DMG를 열고 **Figma Semantic Bridge.app**을 `/Applications`에 복사합니다.
   마운트한 이미지 안의 앱이 아니라 복사한 앱을 실행합니다.
2. macOS가 확인되지 않은 개발자 경고로 실행을 막으면 출처와 무결성을 먼저
   확인합니다. 진행하기로 결정했다면 차단된 실행 시도 뒤 **시스템 설정 →
   개인정보 보호 및 보안 → 확인 없이 열기**를 사용합니다. Gatekeeper를 전체 해제하거나
   격리 속성을 지우지 않습니다. 손상·악성코드 경고는 별도로 다뤄야 합니다.
   [Apple의 실행 안내](https://support.apple.com/en-us/102445)를 따르세요.
3. 앱 안의 편집기가 열릴 때까지 기다립니다. 자동 연결되므로 앱에 토큰을
   붙여넣지 않습니다. **데모 불러오기** 또는 기존 작업 공간을 엽니다.
4. **언어 / Language**에서 한국어나 영어를 고릅니다. 앱 메뉴와 편집기는 같은
   언어를 사용하고, Figma 플러그인의 언어는 별도로 저장됩니다.

앱은 자격 정보를 보내기 전에 로컬 서비스의 비공개 인증서를 확인합니다.
앱·MCP는 `https://127.0.0.1:4178`, 플러그인은 4177 포트를 사용합니다. 두 포트를
외부로 열지 않습니다. 다른 서비스와 충돌하면 해당 서비스의 소유자를 확인해 정상
종료합니다. 포트를 임의로 바꾸거나, 연결 대상이 제시한 인증서를 새로 신뢰하거나,
관계없는 Node 프로세스를 모두 종료하지 않습니다.

**브리지 → 설치 가이드**, **브리지 → 사용 가이드**는 인터넷 없이 안내를 엽니다.
설치 가이드에는 업데이트·백업·복원 절차도 포함됩니다.
**작업 공간 새로고침**은 저장된 편집기를 다시 엽니다. 앱 종료 시 앱이 직접 시작한
하위 서비스만 중지하며, 별도로 관리되는 호환 서비스는 계속 실행됩니다.

## 3. Figma 플러그인 가져오기와 연결

1. 앱을 켜 둔 채 **브리지 → Figma 플러그인 폴더 보기**를 누릅니다.
2. Figma Desktop의 **Plugins → Development → Import plugin from manifest**에서
   열린 폴더의 `manifest.json`을 선택합니다. ZIP을 선택하거나 새 플러그인 ID를
   만들지 않습니다. 코드는 이미 빌드되어 있습니다.
3. 읽을 권한이 있는 파일에서 가져온 플러그인을 실행합니다. Dev Mode에서는
   Inspect의 플러그인 영역, 실행이 허용된 Design Mode에서는 Plugins 메뉴를
   사용합니다. 앱의 원본 읽기에는 편집 동작이 필요하지 않습니다. 다만 보기 권한만
   있고 Dev Mode도 없는 계정에서 플러그인 실행이 가능한지는 별도 권한 문제입니다.
4. 앱의 **브리지 → 연결 토큰 복사**를 누르고 플러그인의 **연결 토큰**에 붙여넣은
   뒤 **연결**을 누릅니다.
5. 플러그인의 연결 상태와 앱의 **Figma 연결됨**을 확인합니다.
   이어서 **브리지 → 복사한 토큰 지우기**를 누릅니다.

연결하면 토큰 입력란은 비워집니다. 토큰을 출력하거나 보고서·MCP 설정에 넣지 말고,
값이 들어 있는 입력란을 촬영하지 않습니다. 앱의 자동 연결과 플러그인 연결은
별개입니다. 동시에 활성화되는 플러그인은 하나이므로 다른 파일로 연결이 바뀌면
원하는 파일의 플러그인을 명시적으로 다시 연결하세요.

별도 플러그인 ZIP을 사용한다면 체크섬을 확인하고 고정된 폴더에 풉니다.
그 폴더의 manifest를 가져오고, 릴리즈마다 앱과 함께 업데이트합니다.
Figma가 경로를 기억하므로 폴더를 옮기면 등록이 끊길 수 있습니다.

이 배포는 로컬 개발 플러그인이며 Figma Community 등록본이 아닙니다.
네트워크 허용 목록을 넓히거나 조직 정책을 우회하도록 manifest를 바꾸지 않습니다.
Dev Mode·파일 접근·로컬 플러그인 가져오기가 막히면 실제 권한 조건을 기록하고,
그동안에는 허용된 전달 파일로 검토할 수 있습니다.

## 4. 작은 작업으로 확인

1. 임시 합성 작업 공간이나 **데모 불러오기**로 시작합니다. 간단한 주석을 저장하고
   앱을 다시 실행해 유지되는지 확인합니다. 기존 작업과 승인은 보존합니다.
2. 실제 Figma에서는 허용된 작은 Frame 하나를 선택합니다. **원본 추가**로
   이름·경계·한도를 확인한 뒤 **가져오기 시작**을 누릅니다.
3. 이미지와 구조는 자동 저장됩니다. 한도에 도달하면 설정을 높여 같은 연결에서 계속할 수 있습니다.
4. [사용 가이드](user-guide.ko.md)에 따라 영역과 정확한 원본 노드를 검토하고,
   적절한 경우 확인·승인합니다. 설치 요청만으로 에이전트가 실제 디자인의 의미를
   사용자 대신 승인할 수 있는 것은 아닙니다.
5. 앱의 파일 저장 창에서 JSON 또는 Markdown을 저장하고, 예상한 승인 맥락만
   담겼는지 확인합니다.

이미지만 있는 초안에는 영역을 그릴 수 있습니다. 승인하려면 일치하는 완전한 구조가
연결되기를 기다리거나, 필요한 부분을 모두 준비해 별도 범위에서 검토하세요.
가져오기와 설정은 [가져오기 가이드](acquisition-workflow.ko.md)를 따르세요.

## 5. MCP 등록과 실제 호출

**브리지 → MCP 설정 복사**로 복사한 항목을 MCP 클라이언트에 추가합니다.
다른 서버와 설정을 덮어쓰지 않습니다. 메뉴는 실제 앱 실행 파일 경로, 데이터
폴더와 HTTPS 주소를 제공하며 토큰은 복사하지 않습니다.

표준 설치 위치와 기본 데이터 폴더를 사용하는 Codex TOML 설정은 다음과 같습니다.

```toml
[mcp_servers.figma_semantic_bridge]
command = "/Applications/Figma Semantic Bridge.app/Contents/Resources/runtime/node"
args = ["/Applications/Figma Semantic Bridge.app/Contents/Resources/app/mcp.mjs"]
env = { FSB_SERVER_URL = "https://127.0.0.1:4178" }
```

앱이나 데이터 위치가 다르면 메뉴에서 복사한 경로와 `FSB_DATA_DIR`를 사용합니다.
MCP는 같은 비공개 데이터 폴더의 연결 토큰과 인증서 정보를 읽습니다. 앱과 MCP를
같은 사용자 계정에서 실행하세요. 이전 HTTP 주소를 사용하거나 인증서 확인을
끄거나 실제 작업에 `FSB_ALLOW_INSECURE_HTTP`를 설정하지 않습니다.

클라이언트 설정을 다시 불러오고 도구 목록을 확인한 뒤 실제로 `list_projects`를
호출합니다. 검토한 작업 공간에서 `get_approved_context`, `list_components`,
`get_component`를 읽습니다. 승인한 내용이 없다면 빈 결과가 정상입니다.
설정 파일 저장만으로 연결 성공을 판단하지 않습니다.

앱은 계속 실행되어야 합니다. 저장된 작업 공간 조회에는 Figma가 필요 없고,
새 원본 읽기와 이동에는 연결된 플러그인이 필요합니다. 전체 문서 대신 필요한
페이지·구성요소를 요청하세요. `propose_changes`는 검토할 제안을 만들 뿐이며,
MCP에는 승인 도구가 없습니다. Figma 원문은 에이전트 명령이 아니라 원본 자료입니다.

## 6. 저장 위치와 자료 취급

기본 폴더는 `~/.figma-semantic-bridge`입니다. **브리지 → 로컬 데이터 폴더 보기**로
실제 위치를 확인합니다. 작업 공간, 가져오기·구조 수집 기록, 원문, 이미지, 이력,
`pairing-token`, 비공개 `desktop-tls` 인증서가 포함됩니다. 앱 실행 파일과는 별개입니다.

저장 파일과 내보낸 원본 파일은 디스크에서 평문입니다. 백업을 비공개로 보관하고,
토큰·인증서 키를 다른 사람에게 전달하거나 로컬 인증서를 시스템 신뢰 목록에
설치하지 않습니다. 외부 AI는 기본적으로 꺼져 있습니다. 제공자 설정만으로
디자인 전송이 허용되지는 않으며, 외부 생성에는 선택한 내용에 대한 요청별 동의도 필요합니다.

## 문제 해결

| 상황 | 다음 조치 |
| --- | --- |
| macOS 실행 차단 | 릴리즈와 무결성을 확인하고 앱별 시스템 절차를 따릅니다. 조직 제한을 우회하지 않습니다 |
| 포트 충돌·호환되지 않는 서비스 | 확인된 이전 앱·서비스를 정상 종료하고 재시도합니다. 0.1.1과 0.3.0 연결 방식을 섞지 않습니다 |
| 로컬 인증서·권한 오류 | 실제 데이터 폴더의 소유자와 비공개 권한을 확인합니다. 폴더를 보존하고 네트워크 인증서를 대신 신뢰하지 않습니다 |
| 앱 편집기가 토큰을 요구함 | 설치 앱의 내장 편집기인지, 시작 상태에 문제가 없는지 확인합니다. 별도 브라우저는 자동 연결되지 않습니다 |
| 플러그인 연결 실패 | 같은 앱·플러그인 버전, 현재 토큰, 실행 중인 앱을 확인합니다. 업데이트한 플러그인을 닫고 다시 실행합니다 |
| 다른 파일로 연결됨 | 원하는 파일에서 다시 연결합니다. 활성 세션은 하나입니다 |
| Dev Mode·개발 플러그인 메뉴 없음 | 실제 좌석, 파일 접근 권한과 조직 정책을 확인합니다 |
| 구조 미완료·플러그인이 바쁨 | 가져오기 패널의 이유를 확인합니다. 이미 실행된 Figma 렌더링은 중단 요청 뒤에도 끝날 때까지 이어질 수 있습니다 |
| MCP 시작 실패 | 내장 실행 파일 경로, 실행 중인 앱, HTTPS 주소와 같은 데이터 폴더를 확인합니다. 자격 정보는 기록하지 않습니다 |
| 미저장 편집·리비전 충돌 | 편집 의도를 보존하고 최신 작업 공간을 다시 불러와 적용합니다. 새 승인을 덮어쓰지 않습니다 |

## 설치 결과 기록

앱·플러그인 버전, 체크섬, 실행 환경, 실제 데모·Figma·MCP 호출과 재시작 결과,
남은 접근 제한을 기록합니다. 토큰, 비공개 노드 식별자와 원문은 제외하세요.
건너뛴 단계는 미검증으로 남깁니다. 합성 자료의 스크립트 승인은 사람의 의미 평가가 아닙니다.

업데이트·백업·복원·삭제는 [업데이트 가이드](upgrade-guide.md),
일상적인 작업은 [사용 가이드](user-guide.ko.md)로 이어가세요.
