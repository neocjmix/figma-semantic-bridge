# Figma Semantic Bridge v0.5.0 — replacement product and implementation contract

**Status:** proposed plan, not implementation. **Authority:** this document and [task acceptance](v0.5.0-task-acceptance.md). Preserve main and v0.4 release history. v0.5 is a deliberate zero-base replacement, not v0.4 feature parity. The [prototype note](../../reference-only/README.md) is non-normative.

## 1. Product and ownership boundary

Bridge is a **local, human-authored semantic overlay on selected Figma node references**. It stores semantic names/descriptions, UI hierarchy and Spec↔UI relationships. It does not scan, reconstruct, approve or generate Figma source structure, and does not implement Fig2Code. A downstream coding agent uses Bridge JSON/read-only MCP plus Figma MCP to retrieve actual node details and build the UI. Source text, screenshot and BBox are *local editing aids*, not semantic export content.

**Only supported source input for v0.5:** one browser bookmarklet reading the current Figma web page URL. It passes the selected node link to a named Bridge browser window; **UI versus Spec is chosen in the Bridge window, not in the bookmarklet**. No plugin, CDP, two-bookmarklet workflow or Figma selection polling.

## 2. Exact user journey

1. `git clone` → `npm ci` → `npm run build` → `npm start`. Local CLI serves browser UI, REST and read-only MCP; no native wrapper, external database or cloud deployment.
2. **Figma PAT gate:** if no token, show a single password input before workspace selection. Validate token and required file-content scope through an appropriate Figma API request, without silently requiring unrelated scopes such as `current_user:read`. Store server-side only in a user-private local config file (mode 0600); environment variable may be supported as a simple override. Invalid token blocks entry. During use, authentication/permission failures block the affected import and show a token re-entry modal; cancellation aborts, not queues. Distinguish invalid token from inaccessible file in error text; neither proceeds. No offline mode, pending-fetch queue, auto-refresh or retry wizard. Never expose PAT in URL, bookmarklet, browser storage, logs, export or MCP.
3. Create/select/delete workspace; without active workspace editor is inaccessible. With a workspace, show **Canvas** and **Regions** peer tabs, initially empty.
4. In Figma web Dev Mode, select a node. Click the **single** bookmarklet. It opens or reuses a named Bridge window with the current Figma node URL encoded in a fragment and a per-invocation nonce. No localhost fetch from Figma origin, CORS bridge, pairing, plugin installation, CDP or credential in the bookmarklet. On initial load and `hashchange`, Bridge reads and clears fragment and presents a compact **UI / Spec** choice. Selection of kind triggers import immediately, without a second confirmation button. Cancel does not import. With no active workspace or valid PAT, block rather than queue.
5. Server parses and validates the Figma URL and fixed Figma API destination, extracting `fileKey + nodeId`. Never fetch arbitrary user-supplied URLs. Fetch selected node metadata with a bounded REST request (`GET /v1/files/:key/nodes?ids=...&depth=1`, with API behavior verified in P0); obtain BBox, name, page provenance where available. Verify permission and identity **before persisting a new region**. A successful node lookup creates/updates the region; PNG/image API fetch runs asynchronously and may fail without undoing the valid region. No full document or subtree scan. Spec TEXT hint is optional and is never required for completion.
6. Canvas displays captured node images at their Figma absolute coordinates, with file/page partitions in a vertical selector so unrelated coordinate systems never overlap. Navigation: pan/zoom/fit. Region: select, adjust local bounds/position, delete, type name immediately on selection or adjustment. All edits autosave. UI/Spec is determined at import, not by a drawing tool. Browser window reuse must preserve workspace and editing context.
7. Regions tab: two **side-by-side independently scrolling lists**. UI regions show cropped visual previews, can reorder and nest UI under UI without depth limit (one parent, no cycles). Spec regions show text hint or name; remain in the Spec catalog while a dragged ghost creates a reference under any UI, including across Figma files/pages. Spec↔UI is N:N. Removing a ghost unlinks only; UI cannot nest under Spec. No mandatory inspector, source candidate search, review drawer, approval or save buttons. Both tabs can be used in any order.
8. JSON and read-only MCP expose stable Bridge IDs, Figma `fileKey + nodeId` (plus page provenance and resolvable URL), kind, human name/description, ordered UI tree and N:N relations. **Exclude** PNG, BBox, text hint, raw Figma text, styles, full node trees and PAT. Agent independently queries Figma MCP for source content and Fig2Code.

**Identity and re-import:** internal Bridge ID is distinct from Figma ID. Uniqueness key is workspace + kind + fileKey + nodeId. Same-kind resend updates Figma metadata/preview but preserves human-authored name, description, local geometry adjustments, tree and relations. Same node may coexist as UI and Spec. The workspace for an import is captured when the user chooses kind; asynchronous metadata/image results cannot attach to a newly selected workspace.

**Page provenance:** bookmarklet URL may lack page ID; derive from returned node ancestry/metadata if supported, or use a narrowly scoped, explicitly tested fallback. Do not claim page identity can always be derived from the node URL alone. If reliable page partition cannot be determined, block spatial placement with an actionable error rather than invent a page. This is a P0 feasibility gate.

**Image mapping:** node `absoluteBoundingBox` is authoritative for placement. Query Figma REST image API for the selected node; request absolute bounds when supported, validate pixel dimensions/aspect ratio and do not silently stretch incompatible images. Missing/failed image shows a nonblocking placeholder. Preview is a historical snapshot.

## 3. Retire/reuse ledger — aggressive replacement

| v0.4 subsystem | v0.5 action |
| --- | --- |
| Swift/AppKit/WKWebView, DMG, signing, native packaging | **Remove** from runtime/build |
| Figma Dev Mode plugin, `capture.ts`, selection/export transport and plugin packaging | **Remove** from v0.5 runtime; historical v0.4 code retained in git |
| DFS structure reader, chunk/cursor/replay/recovery, BBox matching, evidence acquisition | **Remove** |
| WebSocket, pairing, session/auth channel, plugin token | **Remove** |
| Inspector, approval workflow, source review, AI draft/proposals, import settings | **Remove** |
| Old annotation/spec/project schema and historical migration machinery | **Replace** with minimal v0.5 schema; no automatic migration |
| Server/CLI infrastructure | **Reuse only proven small utilities**; rebuild thin local server and static browser app |
| Geometry, file persistence, tests, MCP utilities | **Selectively reuse** after verifying v0.5 contract; avoid obsolete abstractions |
| Existing Figma API credentials and integration knowledge | **Reuse configuration where safe**, but do not depend on v0.4 runtime |
| v0.4 docs/screenshots | Preserve as historical, rewrite current README/guide |

No compatibility layer or preservation mandate. Use an isolated `feat/v0.5-core` implementation branch based on main; preserve v0.4 tag/data and use separate v0.5 storage. Delete obsolete runtime/build paths when integrating. If isolation is demonstrably infeasible, record rationale before proposing an orphan branch. Do not create a new repository by default.

## 4. Minimal architecture

- **Browser bookmarklet:** read `location.href` from Figma web, open/reuse named Bridge window with encoded URL and nonce. No secret, network fetch or kind selection. Installation is a single bookmark instruction.
- **Browser UI:** token gate, workspace gate, import kind chooser, Canvas, Regions. On same-origin Bridge page, fragment handler sends a POST to the local Bridge server only after kind selection; clears fragment and deduplicates a single invocation. Handle repeated identical nodes via nonce. Browser navigation may refocus the Bridge window; accept this as part of the design.
- **Loopback server:** fixed `127.0.0.1` port, clear collision error, static UI, bounded JSON endpoints, workspace storage, token management, Figma REST client, asynchronous image fetch, JSON export and read-only MCP. No generic URL fetch endpoint, arbitrary filesystem paths, shell execution or public binding. CORS not needed for bookmarklet→Bridge navigation; same-origin Bridge UI talks to server. Origin/CORS is not a substitute for authentication. Localhost-only tool explicitly accepts risk from malicious local processes; do not add pairing without approval.
- **Persistence:** choose the least operationally complex local durable store (JSON with atomic writes or SQLite), with no external daemon. Store token separately from workspace data, with restricted permissions. Token never enters JSON/MCP export.
- **Minimal data:** `Workspace{id,name,regions,relations}`; `Region{id,kind,figma:{fileKey,pageId,nodeId,url},name,description?,sourceBBox,localBounds?,previewAssetId?,textHint?,parentUiId?,order}`; `Relation{id,specRegionId,uiRegionId,order?}`. UI hierarchy is acyclic, single-parent, unlimited-depth; relations unique per Spec/UI pair and may cross files/pages. UI-only preview/textHint are not exported.

## 5. P0 feasibility gates (before committing to replacement)

1. **Figma selection URL fidelity:** 20 representative node selections in real Figma web Dev Mode (frames, groups, text, instances, variants, repeated selection). Compare selected node against URL `node-id`; determine exact unsupported cases. If selection URL is unreliable for core nodes, **stop and request architecture decision**; do not silently add CDP, plugin or DOM scraping.
2. **Bookmarklet delivery:** named-window open/reuse, fragment and nonce delivery on first load and repeated sends, hashchange/initial-load handling, popup permissions, no loss when Bridge already open, user-selected UI/Spec kind, and browser behavior with Figma CSP. Test actual browser; do not claim success from synthetic navigation only.
3. **Figma REST:** PAT validation without unnecessary scopes; file/node access, `depth=1` response, page provenance, BBox and image URL/rendering including `use_absolute_bounds`; actual response errors (401/403/404/429), image `null`, URL variants. Confirm selected-node lookup is bounded and does not trigger whole-tree import.
4. **Figma MCP:** downstream agent dereferences `fileKey + nodeId` (or canonical URL) independent of current selection. Existing working MCP is evidence, but validate exported identity end-to-end.

A failed P0 gate requires a short decision note and owner approval before substituting an input architecture. Do not assume CDP or plugin fallback is in scope.

## 6. Delivery phases

**P1:** CLI/browser server, PAT gate and modal, workspace CRUD, fragment receiver and single bookmarklet, validated bounded REST node lookup, durable region record, asynchronous preview. Tests for no token, wrong token, inaccessible file, invalid URL, missing workspace, repeat send, port collision, restart and image failure.

**P2:** Canvas file/page partition, original coordinate placement, pan/zoom/fit, inline typing, local adjustments, delete and autosave. Tests for negative/fractional BBox, page separation, image mismatch and focus.

**P3:** Two independently scrolling Regions lists, UI tree reorder/reparent, Spec ghost N:N, cross-file relations, keyboard alternative, stable ordering and persistence. Tests for cycles, duplicate edges, unlink vs delete and restart.

**P4:** Minimal JSON/read-only MCP with matching semantics, output exclusion assertions and real Figma MCP dereference.

**P5:** Full browser task journey with real Figma web selection → bookmarklet → Bridge kind choice → REST lookup → Canvas/Regions → JSON/MCP. Test at least two files/pages, multiple nested UI nodes and a Spec linked to two UI nodes. Include user comprehension, failure paths and actual screenshot review. Report exact test environment and unresolved external gates.

See [T01–T12 acceptance](v0.5.0-task-acceptance.md) for normative scenarios. Do not call an external gate passed if unverified.

## 7. Codex constraints and definition of done

- **Implement only this contract and T01–T12.** No v0.4 parity, plugin, CDP, AI proposal, source scanning, candidate search, approval state, rich settings, native wrapper, enterprise auth, multi-user sync, cloud service, onboarding wizard or diagnostic dashboard.
- A necessary smallest fix is allowed autonomously only for a reproduced acceptance blocker, with test evidence, and without a new user-facing workflow. Material product additions require an explicit decision note and approval; pause that extension, continue independent work.
- No deferred fetch queue for absent/invalid PAT, no offline mode, no speculative retry system. A valid region may persist with failed **image** only. Do not conflate file-specific 403 with universally invalid PAT.
- Do not use the [UX sketch](../../reference-only/README.md) as source, CSS/DOM template, screenshot oracle or build dependency. Independently design to satisfy tasks.
- Complete each phase with executed tests, environment, commit SHA and recorded failures. Do not declare partial work finished because code compiles.
- Definition of done: clean clone/build/start without native tools; PAT gate; one bookmarklet; stable repeated import with in-app kind choice; source lookup and image preview; working Canvas/Regions; durable semantic tree/N:N relations; JSON/MCP handoff; real Figma and browser E2E evidence. Preserve v0.4 history and data.
