# 수집 중단·자료 재사용·필요한 부분 읽기: 구현과 검증 계획

[English](recovery-plan.en.md) · [상황별 사용자 안내](user-scenarios.ko.md)

**2026-10-27, 0.3.0 구현 기준입니다.** 이 계획의 복구 기능과 제한을 정리합니다.
실행한 소스·브라우저·설치 앱 검사는 [0.3.0 검증 기록](evaluation/release-0.3.0-acceptance.md)에,
최종 공개 패키지의 출처와 해시는 릴리즈에 첨부한 검증 보고서에 남깁니다.

목표는 수집이 중단돼도 받은 자료를 활용하고, 필요한 원본을 확보해 사람의 검토와
승인을 마치는 것입니다. 누락이나 원래 요청 범위의 축소 없이 작업하는 것이 우선입니다.
작업 흐름은 **원본 추가 → 영역·명세 작업 → 원본 확인 → 의미 승인 → 전달** 하나입니다.

## 구현한 범위

| 필요 | 현재 동작 | 지켜야 할 경계 |
| --- | --- | --- |
| 구조 수집이 멈춰도 이미지 사용 | 이미지와 제안 상태의 영역을 따로 보존 | 이미지만으로 원본을 승인할 수 없음 |
| 중단된 자료 확인 | 받은 노드·저장 원문을 나눠 조회하고, 받은 자식 수와 완성된 하위 영역 표시 | 받은 자료만으로 미확인 형제나 현재 Figma 상태를 단정하지 않음 |
| 같은 연결에서 계속 | 읽기 위치가 유효하면 마지막 저장 다음부터 재개 | 오래 쉬거나 원본·연결이 바뀌면 위치가 무효화될 수 있음 |
| 재연결·앱 재시작 후 계속 | 반복 읽기 비용을 설명하고 확인받은 뒤, 원래 대상을 새 기록으로 다시 확인 | 전체 범위 확인에 필요한 필드를 다시 읽음. 단일 시점의 Figma 버전은 보장하지 못함 |
| 같은 저장 자료 재사용 | 실제로 다시 읽은 내용이 정확히 같을 때 짧은 확인 응답으로 대체 | 전송량을 줄이며, 필요한 Figma 속성 읽기까지 생략하지는 않음 |
| 알고 있는 미완료 하위 영역 확보 | 해당 영역과 자손만 별도 수집하고 원래 이미지·상위 작업 연결 유지 | 관련 없는 하위 트리는 읽지 않으며, 원래 전체 작업은 미완료로 유지 |
| 완성한 작은 영역 검토 | 모두 받은 하위 영역을 별도 검토 범위로 연결하고 해당 제안 영역 복사 | 승인은 그 범위만 대상으로 하며, 기존 승인을 자동 이전하지 않음 |
| 코딩 에이전트 사용 | 기본 도구 네 개로 수집 요청·상태·계속·저장 자료 조회 | 이전 수집 도구는 호환 호출만 유지하고 기본 목록에서는 제외 |
| 원본 자료 전달 | 표준 V2 파일로 완전한 수집·완성된 하위 영역·완전한 작은 캡처 전달. 이전 파일도 읽기 지원 | 주석·명세·승인은 전달하지 않으며, 불완전한 전체 범위를 완료로 바꾸지 않음 |

작은 영역을 따로 읽으려면 일시정지한 전체 작업의 읽기 위치를 해제해야 할 수 있습니다.
이때 전체 작업을 나중에 계속하면 다시 읽어야 한다는 비용을 알리고 확인받습니다.
원래 범위 안에 해당 노드가 있는지 먼저 확인하므로, 노드가 밖으로 이동했다면 기존
읽기 위치를 버리지 않고 거절합니다. 작은 영역의 작업도 재시작·재연결 후 원래 범위와
과거 이미지의 출처를 유지합니다.

## 앱이 판단하는 것

일반 사용자는 미리보기만·구조만·읽기 순서·작은 캡처와 큰 수집·노드 ID·복구 알고리즘을
선택하지 않습니다. 앱이 유효한 결과를 저장하고, 가능한 계속 방법을 판단하며, 같은
작업 공간에서 자료를 보여줍니다. 사람은 어느 영역을 작업할지, 어떤 원본과 의미가
맞는지, 큰 반복 비용이나 외부 전송을 허용할지를 판단합니다.

기본 MCP 수집 도구는 `acquire_source_task`, `get_source_task`,
`continue_source_task`, `read_source_evidence`입니다. 프로젝트·승인 자료·제안 도구도
별도로 유지합니다. 수집 준비는 무거운 읽기를 시작하지 않으며 시작 요청이 필요합니다.
작은 영역은 같은 수집 도구의 part-plan/part 요청으로 준비·실행합니다. 이전 호출은
기존 계약을 유지하는 호환 기능이며, 별도 기본 작업 방식이나 동일한 내부 처리의
보장으로 안내하지 않습니다.

## 받은 자료·범위·최신성·검토를 구분

- **받았는가:** 요청한 기록을 검증하고 저장했는지 확인합니다. 원문이 없는 상태는
  실제로 빈 문자열을 받은 상태와 다릅니다.
- **다 읽었는가:** 지정한 원본과 필요한 자손을 모두 받았는지 확인합니다. 저장 순서와
  자식 수로 완성된 하위 영역을 판정할 수 있지만, 아직 받지 않은 자식의 ID를 만들지는 않습니다.
- **현재와 같은가:** 무엇을 언제 다시 읽었는지 기록합니다. 과거 자료를 열거나 원본의
  이름·경계가 같다는 이유만으로 최신 확인이 되지는 않습니다.
- **사람이 검토했는가:** 원본 집합 확인과 의미 승인은 별도의 판단입니다. 자료를
  수집했다고 자동 승인하지 않습니다.

재연결 후 계속하면 별도 수집 기록이 생깁니다. 원문과 노드 순서를 포함해 다시
확인하므로 루트의 이름·경계가 같아도 내부 원문 변경, 추가·삭제·이동·순서 변경을
기존 자료와 같다고 취급하지 않습니다. 같은 자료라는 확인은 실제 읽기 이후에만
성립합니다. 과거 자료·초안·승인 근거는 보존합니다. 이미지와 구조의 관측 시점은
별도로 유지하며, 한 시점에 고정된 현재 Figma 화면이라고 주장하지 않습니다.

합성 실험에서는 모든 노드를 선택적으로 재확인하는 비용이 보통 순회보다 컸습니다.
따라서 기본 복구는 선택적 검사 후 전체를 또 읽는 방식 대신 한 번의 재검사 순회를
사용합니다. 수치는 [실현 가능성 측정](evaluation/recovery-feasibility.md)에 있습니다.

## 지금 지연 조회로 줄이는 비용

저장 메타데이터는 페이지 단위로, 저장 원문은 화면이나 에이전트가 필요할 때만
조회합니다. 받은 이미지를 다시 열거나 확대해도 Figma를 다시 렌더링하지 않습니다.
작은 영역만 수집하면 관련 없는 트리를 피하고, 과거 전체 이미지도 다시 만들지 않습니다.
Figma 읽기가 멈춘 동안에도 로컬 자료 확인과 편집을 계속할 수 있습니다.

**현재 Figma 구조 순회는 요청한 하위 트리의 각 노드에서 원문을 포함한 전체 기록을
읽습니다.** 저장 원문의 지연 조회가 Figma 원문 속성 읽기까지 생략한다는 뜻은 아닙니다.
메타데이터를 먼저 읽고 원문 요구를 따로 충족하는 방식은 후속 범위입니다. 별도 완료
계약이 필요하며 기존의 완전한 원본 보장을 약화하면 안 됩니다. 불완전한 여러 분기를
임의로 합쳐 전체 완료로 만드는 기능도 제공하지 않습니다. 여러 분기에 걸친 구성요소는
선언한 검토 범위 전체에 충분한 근거가 있어야 합니다.

## 계속·재시도·자원 한도

**계속**은 유효한 위치에서 재개하거나 필요한 원본 재검사를 설명합니다. 작업 공간을
복원했다고 무거운 읽기를 자동 시작하지 않습니다. 전체량을 모르면 받은 수량과 상태를
보여주며, 진행률·남은 시간을 지어내지 않습니다. 노드·바이트·시간 한도는 저장 단위
이후 일시정지하며, 계속하기 전에 안전 상한 안에서 설정을 늘릴 수 있습니다.

구조 읽기가 즉시 `PLUGIN_BUSY`로 거절되면 250ms 뒤 **한 번만** 같은 요청을
재시도할 수 있습니다. 원래 요청·실행 시간 한도 안에서만 동작하며, 일시정지·취소·
연결 교체·예산 소진 시 재시도하지 않습니다. 다시 사용 중이거나 시간 초과가 나면
멈추고 **계속**을 기다립니다. 응답이 유실됐더라도 저장된 응답을 같은 위치에서
다시 받아 중복 노드를 만들지 않습니다. 시간 초과는 이미 요청 예산을 썼으므로
자동 반복하지 않습니다. 이미지 렌더링·확정적인 자료 오류·원본 변경도 자동 재시도하지 않습니다.

Figma 자체가 한 부모의 전체 자식 배열을 만들거나 이미지 렌더링을 끝낸 후에야
제어를 돌려줄 수 있습니다. 앱의 한도가 Figma 내부 최대 메모리나 즉시 취소를 보장하지는
않습니다. 전체 문서 미리 읽기나 원본 편집은 필요하지 않습니다.

## 검증과 배포 기준

| 구분 | 필요한 증거 |
| --- | --- |
| 결정 규칙·로컬 통합 | 부분 저장·재시작, 빈 문자열·Unicode 원문, 손상·누락, 자식 수·완료 검증, 내부 원문·트리 변경, 응답 유실, 제한된 재시도, 범위 확인, 과거 자료 보존, 삭제 경쟁 |
| 작은 영역 수집 | 해당 하위 트리만 읽기, 관련 없는 자식·원문 읽기 없음, 중복 이미지 없음, 원래 작업 미완료 유지, 재시작 후 원래 범위·문맥 보존 |
| 브라우저 흐름 | 시작 → 일부 저장 → 중단·다시 열기 → 받은 자료 확인 → 필요한 부분 확보 → 원본 확인 → 의미 승인 → 에이전트 전달 |
| 호환 | 이전 프로젝트·원본 파일 읽기, 이전 MCP 호출 유지, 새 내보내기는 표준 전달 경로 사용 |
| 실제 Figma | 소유 합성 파일에서 원본 변경 없이 연결 수명·읽기 위치 유실·복구·원문·이미지 보존·부분 수집 확인 |
| 최종 패키지 | 전체 소스·빌드·브라우저 검사, 한영 문구, 앱·플러그인·MCP, 업데이트 백업·복원, 파일 해시·로컬 설치 |

구현과 일부 통과한 테스트만으로 브라우저·실제 Figma·최종 패키지 검증을 대신하지
않습니다. 에이전트가 수행할 검증을 기록한 뒤 **0.3.0 Alpha**를 배포합니다. 원래
업무 파일, 다른 소유자의 파일을 실질적인 Dev 전용 계정으로 읽는 조건, 조직 정책은
허용된 접근이나 사람의 판단이 필요합니다. 확보되지 않으면 해당 검증만 따로 보고합니다.

설계 결정은 [ADR 0012](adr/0012-recoverable-source-evidence.md)에, 사용자 관점의
동작과 제한은 [상황별 안내](user-scenarios.ko.md)에 정리합니다.
