# 수집 중단·자료 재사용·필요한 부분 읽기 개선 계획

[English](recovery-plan.en.md) · [현재 상황별 동작](user-scenarios.ko.md)

**2026-10-26 계획 · 0.2.1 반영분과 후속 제안을 구분합니다.**


0.2.1에는 단일 기본 가져오기, 성공 자료 자동 연결, 해상도·수집 예산 설정과 같은 연결에서의 한도 증가·재개를 먼저 반영했습니다. 이 계획의 연결 간 보충·미완료 구조 조회·영역별 완료 판정은 아직 구현된 것으로 주장하지 않습니다.

목표는 **수집이 중단돼도 받은 자료로 작업을 계속하고, 필요한 나머지만 확보해
검토·승인까지 마치는 것**입니다. 빠르게 성공으로 보이게 만드는 것보다 누락 없이
원래 요청을 수행하는 것을 우선합니다.

**제품 원칙: 작업 흐름은 하나만 제공합니다.** 사용자가 수집 방식·읽기 순서·재사용
방식을 고르지 않습니다. 앱이 정확성을 충족하는 경로 중 불필요한 Figma 읽기와
반복 작업이 적은 경로를 결정합니다. 모든 파일에서 가장 빠르다는 보장은 하지 않습니다.

## 바꿀 작업 흐름

**원본 추가 → 영역·명세 작업 → 원본 확인 → 의미 승인 → 전달**

1. Figma에서 원본 영역을 선택하고 **원본 추가**를 누릅니다. 허용된 원본 파일도 같은
   진입점에서 엽니다. 입력 출처가 달라도 이후 작업 방식은 같습니다.
2. 앱이 저장 자료를 확인하고 필요한 읽기를 계획합니다. 기본 요청 범위는 선택한 영역
   전체이며, 범위 탐색과 필요한 필드의 완료 조건을 기록합니다. 별도 수집 모드는 없습니다.
   무거운 읽기를 시작하기 전에 대상·기본 한도·알려진 위험을 시작 화면에 보여줍니다.
3. 같은 작업 공간을 바로 엽니다. 받은 이미지·노드는 자동으로 사용 가능한 자료가 되고
   저장됩니다. 영역 정리와 명세 작업에 맞춰 필요한 원문·분기를 준비합니다. 준비된
   부분과 아직 미확인인 부분을 구분하며, 전체 범위의 요구를 조용히 줄이지 않습니다.
4. 중단되면 받은 자료로 작업을 계속합니다. **계속** 한 동작으로 연결·변경·누락을
   점검하고 적절한 재개나 보충을 실행합니다. 사용자가 복구 방식을 진단할 필요가 없습니다.
5. 충분한 원본을 확보한 영역부터 사람이 원본과 의미를 검토합니다. 전체 요청의
   미완료 상태와 각 영역의 검토·승인 상태는 별도로 표시합니다.

예를 들어 화면 전체 수집이 중간에 끊겼다면 이미지를 유지한 같은 작업 공간에서
받은 노드를 보고 영역 정리를 계속합니다. **계속**을 누르면 앱이 보충 방법을 결정합니다.
먼저 완성한 작은 영역만 검토할 수 있지만 원래 화면 전체의 요청은 미완료로 남습니다.

## 제거할 선택지와 앱이 맡을 판단

| 현재 또는 이전 계획의 선택 | 개편 후 처리 |
| --- | --- |
| 미리보기만 / 구조만 / 미리보기 먼저 / 구조 먼저 | 제거. 현재 작업에 필요한 자료와 실행 순서를 앱이 결정 |
| 작은 캡처 / 큰 구조 수집 / 필요한 노드 조사 중 선택 | 별도 시작 경로 제거. 하나의 작업이 내부에서 필요한 읽기 사용 |
| 이미지로 초안 만들기 / 이미지 없이 원본 사용 | 별도 복구 버튼 제거. 정상 수신한 자료를 같은 작업 공간에서 자동 사용 |
| 이어 읽기 / 처음부터 읽기 / 보충 / 저장 자료 재사용 | **계속**으로 통합. 앱이 출처·변경·누락·비용을 확인해 실행 |
| ID 입력·부모 목록 페이지 요청·하위 분기 수집 | 일반 UI에서 제거. 검색·Figma에서 선택·영역 작업이 필요한 원본 읽기로 연결 |
| 성공한 결과를 별도로 캡처 저장·구조 추가·이미지 연결 | 별도 완료 절차 제거. 검증된 자료를 자동 저장하고 작업에 연결 |
| 이전 자료를 찾으러 여러 수집 기록 패널 이동 | 작업 공간의 자료 상태와 기록으로 통합 |
| 작은 캡처 전달 / 큰 구조 원본 전달 중 선택 | 새 원본 전달은 하나의 표준 경로. 이전 파일 읽기는 호환 유지 |

이 선택지를 고급 설정으로 옮겨 다시 선택하게 하지 않습니다. 기존 파일 읽기와
에이전트 연동에 필요한 내부 기능은 유지하되 같은 작업 관리와 검증 규칙을 사용합니다.
에이전트에게도 같은 목적의 중복 수집 도구를 나열하지 않고, 작업 요청·진행 확인·
자료 조회 중심으로 정리합니다. 이전 연동의 호환 처리가 별도 수집 방식을 만들면 안 됩니다.
원본 파일 열기, 백업, 검토 결과 전달은 목적이 다른 기능이므로 필요한 위치에 남깁니다.

사용자에게 남길 판단은 **무엇을 작업할지, 어느 원본과 의미가 맞는지, 원래 범위를
바꿀지, 추가 비용·위험이 큰 작업을 진행할지, 외부 전송을 허용할지**입니다.
승인과 원본 확인은 사람의 서로 다른 판단이므로 자동화하거나 합쳐 없애지 않습니다.

## 먼저 정해야 할 안전 기준

| 구분 | 판단 기준 |
| --- | --- |
| 자료를 받았는가 | 요청한 ID·필드·자식 목록을 실제로 받고 검증·저장했는가 |
| 범위를 다 읽었는가 | 읽어야 할 하위 영역을 모두 확인했는가. 노드 수나 화면의 겹침만으로 판단하지 않음 |
| 지금 원본과 같은가 | 어떤 항목을 언제 다시 확인했는가. 예전 자료를 다시 열었다고 최신 확인으로 표시하지 않음 |
| 사람이 검토했는가 | 충분한 원본을 바탕으로 정확한 노드 집합과 의미를 명시적으로 승인했는가 |

**현 플러그인 경로는 여러 번 읽는 동안 고정되는 원본 버전을 제공받지 않습니다.**
따라서 재연결 후 모든 옛 자료가 최신이라는 보장과, 빠진 부분만 읽으면 된다는 보장을
동시에 줄 수 없습니다. 원본 이름·크기가 같거나 사용자가 변경하지 않았다고 답하는
것만으로 이 문제를 해결한 것으로 취급하지 않습니다.

재사용한 과거 자료와 새 읽기를 함께 제공할 때는 각 관찰 시점을 보존합니다.
‘저장된 자료에서 요청 범위가 갖춰짐’과 ‘현재 Figma의 한 시점 전체를 보장함’을
구분합니다. 후자가 필수인 작업은 검증된 제공 경로가 없으면 미지원으로 남깁니다.

## 구현 순서와 완료 조건

| 순서 | 개선 내용 | 사용자가 얻는 결과 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- | --- |
| 0 | 재연결 뒤 무엇을 검증·재사용할 수 있는지 작은 실험 | 안전하게 보충할 수 있는 조건과 다시 읽어야 하는 조건 확정 | 같은 이름·크기인 채 내부가 바뀌는 경우, 새 레이어 추가·삭제·이동을 구분하는 실험 결과 기록 |
| 1 | 단일 작업 공간과 성공 자료 자동 사용 | 받은 이미지로 바로 영역 정리, 완전한 구조는 이미지 없이 사용 | 모드 선택·별도 결과 저장 없이 이미지·구조 실패/중단/재실행 조합에서 정상 자료 재사용 |
| 2 | 받은 부분 열기와 필요한 자료 목록 저장 | 중단 자료의 노드·원문 조회와 제안 작업. 없는 자료와 완료된 하위 영역 확인 | 앱 재시작 후에도 자료·미완료 범위·출처가 보존되고 누락·손상은 미확인으로 유지 |
| 3 | 필요한 부분 보충과 재연결 후 복구 | 이미 저장된 자료를 재사용하면서 필요한 분기·노드·원문만 요청 | 변경·삭제·순서 변경·응답 유실에도 누락과 중복이 없고 원래 목표 범위가 유지됨 |
| 4 | 영역별 검토·승인과 전체 작업 상태 연결 | 완료한 작은 영역을 큰 이미지 위에서 검토하고 전달. 나머지 작업은 미완료로 유지 | 각 승인의 근거 범위·필드가 충분하고, 미확인 범위는 완료·승인 결과로 나오지 않음 |
| 5 | 중복 경로 제거·가이드·배포와 기존 자료 보존 검증 | 한 흐름과 상황별 주 동작 하나, 기존 작업을 유지한 업데이트 | 옛 선택지와 중복 패널 제거, 전체 회귀 검사와 실제 소유 합성 Figma·패키지·백업·복원 검증 통과 |

0과 1은 독립적으로 진행할 수 있습니다. 2의 저장·누락 판정 기준이 확정된 뒤 3을,
그 결과를 바탕으로 4를 연결합니다. 화면 개선만 끝내고 복구가 완성됐다고 발표하지 않습니다.

### 0. 보충 가능성부터 검증

- 이전에 받은 목록, 원문과 관찰 시점을 보존한 채 연결을 끊고 다시 연결합니다.
- 이름·경계가 그대로인데 내부 텍스트·레이어·부모·순서가 바뀐 경우를 시험합니다.
- 어떤 부모의 전체 자식 목록을 다시 확인해야 미수신 분기를 찾을 수 있는지 측정합니다.
- 저장한 자식 수만 있고 아직 ID를 모르는 경우를 ‘빠진 노드 목록을 안다’고 취급하지 않습니다.
- 검증에 필요한 읽기가 전체 재수집에 가까우면 그 비용을 그대로 보고합니다.
  재사용을 위해 더 비싼 검사를 하는 경로를 기본값으로 삼지 않습니다.

이 단계에서 막혀도 1과 2는 진행할 수 있습니다. 보충이 안 되는 경우에도 받은 자료를
열고 제안 작업을 계속할 수 있어야 합니다.

### 1. 성공한 이미지·구조부터 살리기

- 원본 추가로 작업 공간을 준비하고, 이미지가 도착하면 같은 화면에서 영역을 그릴 수
  있게 합니다. 별도의 이미지 초안 생성 단계를 거치지 않습니다.
- 구조가 완전하고 이미지가 실패했어도 같은 화면의 원본 자료는 사용할 수 있습니다.
  이미지는 현재 목적에 꼭 필요할 때만 다시 요청합니다.
- 중단한 작업도 정상 결과는 자동 보존·연결합니다. **계속**은 필요한 나머지만 처리합니다.
- 단, 원본 변경으로 두 결과가 충돌하면 함께 묶지 않습니다. 각각의 관찰로 보존합니다.
- 이미지 초안 저장으로 작업 공간이 바뀌어도 진행 중인 읽기의 대상은 바뀌지 않게 합니다.
  늦은 응답이 다른 작업 공간이나 초안을 덮지 못하도록 확인합니다.

### 2. 받은 부분과 없는 부분을 구분해 저장

- 노드 정보, 바로 아래 목록, 원문, 이미지를 따로 추적합니다. 원문을 아직 안 읽었으면
  빈 문자열로 표시하지 않습니다. 읽기 실패와 요청하지 않은 상태도 구분합니다.
- 검증된 저장 자료만 페이지별로 엽니다. 원문은 고를 때 읽고, 받은 이미지 확대는
  Figma에 다시 요청하지 않습니다.
- 일부만 받은 자료는 조사와 제안에 사용합니다. 위치 기반 후보는 ‘받은 자료 안에서
  찾은 후보’라고 표시하며 전체 원본 검색 결과로 제시하지 않습니다.
- 끝까지 읽은 하위 영역을 판정할 수 있으면 그 범위를 별도 기록합니다. 아직 모르는
  형제 영역과 바깥 레이어는 미확인으로 남깁니다.
- 기존에 중단된 0.2.0 자료도 검증 후 열 수 있게 합니다. 저장하지 않았던 자식 ID나
  옛 원문의 추가 정보를 사후에 만들어 넣지는 않습니다.

### 3. 나머지를 보충하되 옛 자료를 덮어쓰지 않기

- 요청과 결과를 저장한 뒤 다음 부분으로 넘어갑니다. 응답을 잃어도 같은 부분을
  다시 확인할 수 있고, 두 번 받은 자료가 두 노드가 되지 않아야 합니다.
- 같은 연결에서는 기존 이어 읽기를 사용합니다. 재연결 뒤에는 새 읽기로 시작하고
  이전 자료를 비교·재사용합니다. 사라진 내부 읽기 위치를 복원했다고 가장하지 않습니다.
- 새 목록에서 추가·삭제·이동·순서 변경을 발견하면 관련 분기를 다시 확인합니다.
  이름·위치가 같다는 이유로 텍스트나 아래 레이어까지 같다고 추정하지 않습니다.
- 받은 관찰은 변경하지 않고 새 관찰을 추가합니다. 같은 ID의 서로 다른 내용은
  구분하며, 충돌이 해결되기 전에는 자동으로 하나의 완전한 원본으로 합치지 않습니다.
- 처음 단계에서는 기존 전체 수집의 의미를 바꾸지 않고, 검증된 완전한 분기부터
  재사용합니다. 넓은 범위의 통합은 누락 검증이 성립하는 경우에만 확장합니다.

### 4. 필요한 범위만 완성해도 작업할 수 있게 하기

- 큰 이미지와 그 위에 그린 영역을 유지합니다. 완료된 작은 원본을 별도 자료로
  추가하더라도 영역을 처음부터 다시 그릴 필요가 없도록 연결 방식을 개선합니다.
- 첫 승인 경로는 **끝까지 확인된 하위 영역**입니다. 전체 이미지나 바깥 형제까지
  완성됐다는 뜻으로 표시하지 않습니다.
- 연동 에이전트가 처음부터 특정 ID들의 정보·원문만 요청했다면 그 요청의 완료를
  표시할 수 있습니다. 일반 사용자에게 ID 입력 모드를 제공하지는 않습니다. 그림에서
  모든 관련 노드를 찾는 작업을 일부 ID 조회로 바꾸어 완료 처리하지도 않습니다.
- 여러 분기에 걸친 하나의 구성요소는 필요한 모든 분기의 근거가 갖춰져야 합니다.
  아직 읽지 않은 곳에 관련 레이어가 없다고 단정할 수 없으면 원본 탐색은 미완료입니다.
- 이전에 승인한 내용은 과거 근거와 함께 보존합니다. 새 자료가 생겼다고 이전 승인을
  덮거나 새 원본에 자동 적용하지 않습니다. 변경된 내용은 새 검토 대상으로 만듭니다.

## 상태별 화면과 주 동작

다음은 예정 문구입니다. 현재 제공되는 버튼은 아닙니다. 각 상태에는 권장 주 동작을
하나만 둡니다. 자료 보기·상세 기록은 같은 화면에서 제공하고 수집 경로 선택으로 만들지
않습니다. 진행 중 **일시정지**는 항상 가능하며 대체 알고리즘 선택과는 구분합니다.

| 상황 | 안내와 앱의 처리 | 주 동작 |
| --- | --- | --- |
| 원본 없음 | 선택한 원본을 확인하고 하나의 작업 생성 | 원본 추가 |
| 시작 전 대상 확인 | 대상·한도·위험을 읽고 같은 작업의 준비 시작 | 시작 |
| 자료 준비 중 | 받은 이미지·노드를 같은 작업 화면에 표시하고 정상 결과 저장 | 일시정지 |
| 이미지 성공, 구조 중단 | “이미지로 작업할 수 있습니다. 원본 구조는 일부만 받았습니다.” 영역 작업은 그대로 가능 | 계속 |
| 구조 성공, 이미지 없이 검토 가능 | “원본 노드는 사용할 수 있습니다.” 불필요한 이미지 재요청 없이 검토 준비 | 원본 확인 |
| 현재 작업에 필수인 이미지 실패 | 구조 자료는 유지하고 필요한 이미지 재요청을 준비 | 계속 |
| 같은 연결에서 일시정지 | 저장한 부분을 유지하고 이어 읽기 | 계속 |
| 재연결 뒤 중단 자료 발견 | 원본 변경 점검 후 재사용·보충·필요한 재수집을 앱이 결정 | 계속 |
| 넓은 재수집·추가 비용이 필요 | 다시 읽을 범위·이유·보존되는 작업을 먼저 설명 | 해당 작업 진행 확인 |
| 일부 영역만 준비됨 | 준비된 영역은 원본 확인 가능. 전체 요청은 계속 미완료로 표시 | 진행 중이면 일시정지, 멈췄으면 계속 |
| 검토할 영역의 원본 충분 | 저장된 근거를 검토. 다른 영역의 준비 상태와 구분 | 원본 확인 |
| 원본 확인 완료 | 이름·역할·경계·관계의 의미를 검토 | 의미 승인 |
| 승인 완료 | 승인된 근거와 의미를 전달 | 전달 |

전체 분량을 모르면 퍼센트나 남은 시간을 만들지 않습니다. 실제 받은 수량과
남은 요구 사항을 보여줍니다. 재검사·재수집을 시작하기 전 범위, 다시 읽을 항목,
예상할 수 없는 비용과 기존 작업에 미치는 영향을 안내합니다.

가벼운 자동 복구는 기존 허용 범위·예산 안에서만 수행합니다. 일시적인 통신 실패는
중복 실행이 안전한 요청에 한해 횟수를 제한해 재시도합니다. 같은 한도·자료 오류를
반복하거나, 아직 끝나지 않은 이미지 렌더링을 다시 시작하지 않습니다. 앱 재실행 시
과거 작업 화면은 복원하되 무거운 새 읽기는 사용자가 **계속**을 누르기 전 시작하지 않습니다.

## 비용과 Figma 부담을 줄이는 원칙

1. **저장 자료 조회가 먼저**입니다. 다만 과거 조회와 현재 원본 확인을 구분합니다.
2. **필요 필드만 읽습니다.** 구조·목록 확인에 모든 원문이나 이미지를 읽지 않습니다.
   원문이 필요한 명세는 해당 원문을 끝까지 읽고 그대로 보존해야 합니다.
3. **구조 완료와 원문 완료를 구분합니다.** 새 경로의 완료 조건에 포함한 필드가
   빠지면 미완료이며, 기존의 완전한 수집 형식 의미는 약화하지 않습니다.
4. **Figma의 무거운 읽기는 하나씩** 실행합니다. 로컬 자료 조회·화면 편집·검증은
   충돌하지 않는 범위에서 병행합니다. 이미지와 구조를 무조건 동시에 요청하지 않습니다.
5. **재시도는 원인이 해소될 때만** 합니다. 같은 한도 초과를 반복하지 않습니다.
6. **바뀐 범위 중심 재검사**를 목표로 하되, 변경 위치를 신뢰할 수 없으면 더 넓은
   재검사가 필요합니다. 모든 파일의 Figma 내부 메모리·렌더링 시간을 보장하지 않습니다.

## 검증과 배포 기준

- 결정 규칙: 중복 응답, 일부 저장 후 강제 종료, 새 자식 추가·삭제·이동·순서 변경,
  이름·경계가 같은 내부 변경, 원문 미수신·빈 원문·긴 원문을 자동 테스트합니다.
- 실제 사용자 경로: **시작 → 일부 저장 → 중단 → 앱 재시작 → 받은 자료 열기 →
  필요한 범위 보충 → 원본 확인 → 의미 승인 → 에이전트 전달**을 브라우저에서 검증합니다.
- 단일 흐름: 노드 수·구조·이미지 실패·재연결 조합이 달라도 사용자가 수집 모드를
  고르거나 기록 패널을 옮겨 다니지 않고 완료하는지 검증합니다. 한도·순서·원본 ID를
  입력해야만 복구되는 경로는 일반 사용자 시나리오의 성공으로 인정하지 않습니다.
- 부정 경로: 빠진 형제·손상된 자료·미확인 원문·미승인 의미가 완료나 승인 결과로
  섞이지 않는지, 기존 승인·자료가 그대로인지 확인합니다.
- 실제 Figma: 소유 합성 파일에서 읽기 전용 중단·재연결·변경·원문 조회를 실행하고
  선택·문서 변경 여부와 읽은 요청 수·노드·바이트·시간을 기록합니다.
- 측정할 항목: 중단 전후 재사용 분량, 반복 읽기 분량, 변경 확인 비용, 원래 요청의
  누락 여부. 빠르다는 인상이나 첫 이미지 시간만으로 성공을 판단하지 않습니다.
- 전체 0.2.0 회귀 검사, 한국어·영어 문구, 업데이트·백업·복원을 확인합니다.
  새 자료 연결 방식이 추가되므로 **0.3.0 Alpha**를 목표로 하되, 기능·검증 완료 전에는
  버전만 올리거나 기존 공개 파일을 교체하지 않습니다.

개발·합성 검증·패키징은 에이전트가 진행할 수 있습니다. 원래 업무 파일과 다른
소유자의 보기 전용 계정 검증은 허용된 접근이 필요합니다. 그 조건이 없으면 해당
검증만 미확인으로 남기고 독립적인 개발 작업은 계속합니다.

구조 변경 제안은 [ADR 0012](adr/0012-recoverable-source-evidence.md)에 기록했습니다.
이 문서는 계획이며, 현재 가능한 기능은 [상황별 동작](user-scenarios.ko.md)을 따릅니다.
