# Figma Semantic Bridge 0.1.1 알파 사용자 가이드

[English](user-guide.en.md) · [설치와 MCP 설정](alpha-installation.md) · [README](../README.md)

설치·사용 가이드는 패키지에 포함됩니다. README·검증·릴리스 같은 다른 문서 링크는
원본 저장소용 참고 링크이므로 단독 문서나 플러그인 ZIP에서는 열리지 않을 수 있습니다.

이 앱은 Figma 원본을 고치지 않고, 사람이 검토한 의미와 요구사항을 별도로 저장합니다.
먼저 작은 화면을 캡처하고, 영역과 원본 노드의 연결을 확인한 뒤, 의미를 승인해
코딩 에이전트에게 전달하세요. 설치한 앱은 내장 편집기에 자동 연결됩니다.
Figma 플러그인에는 앱의 **페어링 토큰 복사(Copy Pairing Token)**으로 복사한 토큰을 붙여넣습니다.

**0.1.1 알파의 공개 릴리스는 LICENSE 선택을 기다리며 아직 게시되지 않았습니다.**
설치 파일과 실제 검증 범위는 설치 문서를 확인하세요. 이 가이드는 사용 절차이며
독립된 의미 전문가의 정확도 평가나 생산성 검증 결과가 아닙니다.

## 화면 언어

앱 상단 오른쪽 **Language / 언어**에서 **한국어** 또는 **English**를 선택합니다.
브라우저는 선택을 저장하고, 저장을 사용할 수 없으면 현재 세션 동안 유지합니다.
브라우저의 첫 기본값은 `navigator` 언어를 따릅니다. macOS 앱은 OS의 첫 번째 선호
언어로 시작하고 앱 메뉴와 내장 편집기의 선택을 동기화합니다. Figma 플러그인은
자신의 언어 선택을 별도로 저장합니다.

**언어를 바꿔도 프로젝트 이름, 사람이 쓴 주석, Figma 노드 이름·원문, 명세와
승인된 콘텐츠는 번역하거나 변경하지 않습니다.** 표시용 UI 언어만 바뀝니다.
이 문서는 한국어 설명에 영문 버튼 이름을 함께 적어 어느 언어에서도 찾도록 했습니다.
오류 코드, 식별자나 역할 값은 영어로 보일 수 있습니다.

## 가장 짧은 권장 순서

1. Figma에서 허용된 **작은 Frame 하나**를 선택하고 **Figma 선택 영역 캡처(Capture Figma selection)**.
2. 앱에서 영역을 그리고 이름을 쓴 뒤 **주석 저장(Save annotation)**.
3. **원본 연결 찾기(Match source)**로 후보와 경고를 확인.
4. 모호하면 **Figma에서 보기(Show in Figma)** 또는 **현재 이미지 비교(Compare current export)**로 직접 확인.
5. 원하는 노드를 하나씩 선택해 **현재 Figma 선택 추가(Add current Figma selection)**으로 누적.
6. 참조를 정리한 뒤 다시 **주석 저장(Save annotation)**.
7. 사람이 저장된 참조 집합을 검토하고 **출처 확인(Confirm sources)**.
8. 구성요소의 의미·이름·역할·상위 관계를 검토하고 **주석 승인(Approve annotation)**.
9. **명세(Specifications)**에서 정확한 원문을 선택하고 관계를 저장·승인.
10. **JSON 내보내기(Export JSON)**, **Markdown** 또는 MCP로 승인된 문맥 전달.

Figma가 없으면 받은 캡처 bundle을 가져오거나 **데모 불러오기(Load demo)**로 시작할 수 있습니다.
새로운 원본 읽기와 Figma 탐색에는 실행 중인 플러그인이 필요합니다.

## 1. 무엇을 캡처할지 정하기

Workspace에서 새 작업 이름을 입력하고 `+`로 만듭니다. Figma에서 작은 컨테이너를
선택한 뒤 앱의 **Figma 선택 영역 캡처(Capture Figma selection)**을 누르세요. 설명이나 규칙이 다른
Frame에 있으면 별도로 캡처해 같은 workspace에서 검토합니다.

**원본 캡처(Source captures)**의 노드 수, complete/partial 상태, 이미지와 경고를 확인합니다.
부분 캡처를 전체 범위로 취급하지 마세요. 제한에 걸리면 필요한 작은 하위 범위를
명시적으로 선택합니다. 파일 전체나 다른 페이지를 미리 읽을 필요는 없습니다.

이미지는 캡처 시점의 합성 화면입니다. SECTION은 메타데이터만 가져오고 PNG는 없습니다.
회전·반사·기울임 때문에 root 이미지 매핑이 지원되지 않을 때도 경고를 보존합니다.
이미지가 필요하면 회전하지 않은 내부 Frame을 선택하세요.

## 2. 영역의 이름과 의미를 저장하기

캔버스에 영역을 그리거나 **+ 영역 추가(+ Add region)**을 사용합니다. **구성요소 이름(Component name)**에는
구현에서 의미 있는 이름을, **역할(Role)**에는 역할을 지정합니다. 필요한 경우
**상위 구성요소(Parent component)**로 의미상 상위 항목을 정합니다. 이 관계는 Figma 레이어 트리와
독립적이며, 화면에서 들어맞는 사각형만으로 자동 결정할 수 없습니다.

숫자 좌표는 Figma 문서 좌표입니다. 음수 위치도 가능하며 화면 확대율이나 앱 창의
픽셀 좌표가 아닙니다. **주석 저장(Save annotation)**을 눌러 저장한 다음 매칭·확인을 진행합니다.
영역 이동, 크기 변경, 이름 입력과 참조 추가는 저장 전 초안일 수 있습니다.

## 3. 후보를 해석하고 직접 비교하기

**원본 연결 찾기(Match source)**는 기하 관계로 원본 노드를 제안합니다. coverage/IoU가 높거나
후보 순서가 앞선다고 의미가 맞거나 새 디자인이라는 뜻은 아닙니다. 동일한 위치에
여러 노드가 있으면 후보와 ambiguity를 함께 살펴보세요.

| 확인 도구 | 보여 주는 것 | 하지 않는 것 |
| --- | --- | --- |
| 캡처 영역 미리보기(Preview captured area) | 저장된 합성 이미지의 해당 영역 crop | 겹친 레이어 분리나 현재 Figma 상태 재조회 |
| Figma에서 보기(Show in Figma) | 원본 파일/페이지 확인 후 노드 선택·뷰포트 이동 | 원본 노드의 디자인·원문 수정 |
| 현재 이미지 비교(Compare current export) | 클릭 시점의 노드 하나와 하위 렌더링 PNG | 출처 추가·확인·의미 승인·저장 캡처 교체 |
| 비교 크게 보기(Enlarge comparison) | 이미 받은 두 이미지 확대 | 새로운 Figma export 요청 |

저장 crop과 현재 export는 서로 다른 시점의 이미지입니다. 현재 export는 바깥 형제를
포함하지 않으며 ancestor opacity·mask·clip·blend 적용을 일반적으로 보장하지 않습니다.
현재 이미지 요청은 최대 1024px·2MB, 5초의 협력적 제한을 사용합니다.
빈 PNG도 특정 원인의 증거가 아닙니다. **현재 이미지 닫기(Close current export)**는 대기 요청을 취소하고
결과를 닫지만 Figma 내부 렌더링이 즉시 중단됐다는 뜻은 아닙니다.

## 4. 정확한 노드 집합을 만들기

Figma에서 의도한 노드를 선택하고 앱의 **현재 Figma 선택 추가(Add current Figma selection)**을 누릅니다.
트리상 멀리 떨어진 노드도 하나씩 반복해 같은 영역의 초안에 모을 수 있습니다.
중복 선택은 중복 참조를 만들지 않습니다. 불필요한 참조를 제거하고
**주석 저장(Save annotation)**으로 집합을 저장하세요. 캡처된 노드 검색과 페이지 이동도 이용할 수 있습니다.

한 annotation의 참조는 **같은 저장 캡처 안**에 있어야 합니다. 필요한 노드가 밖에
있으면 그 노드들을 포함하는 제한된 공통 컨테이너를 새로 캡처하거나, 별도 영역으로
나눈 뒤 명세를 여러 구성요소에 연결합니다. 서로 다른 snapshot의 참조를 한 annotation에
자동 합치는 기능은 없습니다. 파일·페이지·선택 메타데이터가 달라지면 추가가 거부될 수 있습니다.

## 5. 출처 확인과 의미 승인을 나누기

**출처 확인(Confirm sources)**는 “이 저장된 원본 참조 집합을 내가 확인했다”는 판단입니다.
**주석 승인(Approve annotation)**은 이름·역할·경계·상위 관계의 의미가 구현 문맥으로 적절하다는
별도 판단입니다. 이미지 보기나 제안 수락은 어느 쪽도 자동 수행하지 않습니다.

모호한 후보, 수동으로 고른 hidden/transparent 참조, 새 렌더링 정보의 unknown 참조는
출처 확인이 필요할 수 있습니다. 확인이 막히면 먼저 참조와 초안 저장 여부를 확인하세요.
비교 후에도 의도가 불분명하면 proposed 상태로 남겨 두고 작성자에게 필요한 판단을
확인합니다. 성공 표시를 만들기 위해 승인하지 않습니다.

원본 참조나 영역을 바꾸면 이전 확인을 새 초안의 확인으로 취급하지 않습니다.
수정 후 다시 저장·검토하세요. 이미 승인된 기록을 AI가 자동 교체하지 않습니다.
승인된 자식이라도 의미상 부모가 미승인인 경우 승인 문맥에서 제외될 수 있습니다.

## 6. 정확한 명세 원문과 관계 연결하기

1. **명세(Specifications) → 원본 텍스트 선택(Select source text)**에서 캡처된 TEXT를 선택합니다.
   UI와 별도 설명 캡처의 원문도 사용할 수 있고 선택 순서가 보존됩니다.
2. **명세 만들기(Create specification)**을 눌러 원문을 확인합니다. 설명을 의역해서 원문인 것처럼
   저장하거나 화면의 모든 글을 자동으로 요구사항으로 취급하지 않습니다.
3. 적용할 구성요소를 선택하고 관계를 정합니다: `describes` 설명, `behavior` 동작,
   `constraint` 제약, `interaction` 상호작용, `dependency` 의존.
   하나의 명세를 여러 구성요소에 연결할 수 있습니다.
4. **명세 저장(Save specification)**을 누릅니다. 대상 구성요소를 먼저 검토·승인한 뒤
   **명세 승인(Approve specification)**으로 명세와 그 연결을 함께 검토합니다.

이미지 속 글자, Figma 댓글·native annotation이 자동 추출된다고 가정하지 마세요.
이 흐름에서 고르는 근거는 실제 캡처에 들어 있는 TEXT입니다. 언어 전환도 원문을 바꾸지 않습니다.

## 7. 코딩 에이전트에게 전달하기

상단 **JSON 내보내기(Export JSON)**과 **Markdown**은 승인된 구현 문맥을 내보냅니다. 파일 저장
대화상자에서 위치를 선택합니다. MCP에서는 `list_projects`로 작업을 찾고
`get_approved_context`, `list_components`, `get_component`를 필요한 범위만 읽습니다.
앱은 계속 실행해야 하며 캐시 읽기에는 Figma 연결이 필요하지 않습니다.

출력이 비어 있으면 annotation·상위 관계·명세 대상이 승인됐는지 먼저 확인하세요.
MCP 연결 문제를 해결하려고 대신 승인하지 마세요. `propose_changes`는 사람이 검토할
제안만 저장합니다. MCP에 승인 도구는 없으며 원문에 포함된 명령은 에이전트 지시가 아닙니다.

## 상황별 다음 동작

| 상황 | 권장 동작 |
| --- | --- |
| 의미 영역이 먼 레이어 브랜치에 걸침 | 같은 캡처에 있는 정확한 노드를 한 번에 하나씩 현재 Figma 선택 추가 → 주석 저장. 밖에 있으면 제한된 공통 범위를 재캡처하거나 annotation 분리 |
| hidden 또는 opacity 0 | 자동 후보에서 제외돼도 원본 기록은 남음. 필요하면 수동으로 선택·비교·확인. 원본 속성을 바꿔 드러내지 않음 |
| 위 레이어에 완전히 덮인 옛 디자인 같음 | Figma 레이어와 현재 export를 비교하되 겹침·순서만으로 old/new 자동 확정 금지 |
| 후보가 여러 개이고 의도가 불명확 | 후보를 비교하고 proposed 유지. 결정적인 정렬은 의미 확신이 아님 |
| Figma 사용 불가/오프라인 | 캡처 전달(Capture transfer)로 받은 bundle을 새 workspace에 가져와 검토. live 선택·탐색·현재 export는 불가 |
| Dev Mode 또는 파일 접근 불가 | 실제 seat·can-view·조직 정책 확인. 소유 파일 성공은 타인 파일 Dev-only 검증이 아님. 권한 확대·복제 반복으로 우회하지 않음 |
| SECTION/변형 root의 이미지 없음 | 경고와 메타데이터를 보존하고 이미지용 내부 unrotated Frame 선택 |
| 원본 변경 또는 오래된 캡처 | metadata 변경 오류면 새 캡처 후 사람이 다시 연결. 일부 스타일/하위 변경은 검출되지 않으므로 현재 이미지 비교도 freshness 보증은 아님 |
| Revision conflict | 미저장 의도를 기록한 뒤 새로고침(Refresh)으로 최신 상태를 읽고 필요한 편집만 재적용 |
| 미저장 초안/비활성 버튼 | 주석 저장(Save annotation)/명세 저장(Save specification) 여부와 연결·진행 중 작업을 확인. workspace를 바꾸기 전에 저장; 모든 전환이 초안을 보존한다고 가정하지 않음 |
| partial scope/시간·크기 제한 | 더 작은 명시적 범위 선택. partial을 complete로 표시하거나 PNG 한도를 올려 반복하지 않음 |
| Wrong file/page/session | 저장 캡처와 맞는 원본·페이지·플러그인 세션을 확인. URL에서 ID를 추측해 기록을 보정하지 않음 |
| AI generation 비활성 | 알파 앱의 기본 상태. 수동 작업과 구조화된 제안 검토는 가능; 외부 provider를 자동 활성화하지 않음 |

## 내보내기와 백업의 차이

| 필요 | 기능/방법 | 포함 범위 |
| --- | --- | --- |
| 다른 사람이 원본 관측을 검토 | 캡처 전달(Capture transfer) → 캡처 내보내기(Export captures) / 캡처 가져오기(Import captures) | 최대 두 캡처의 원문·좌표·출처·PNG·경고. 새 workspace 생성; annotation·명세·승인 제외 |
