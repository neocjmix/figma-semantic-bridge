# Figma Semantic Bridge 0.2.0 Alpha 사용 가이드

[English](user-guide.en.md) · [설치·MCP](alpha-installation.md) · [가져오기 방법](acquisition-workflow.ko.md)

**원본 가져오기 → 영역 표시 → 정확한 노드 확인 → 의미 승인 → 코딩 맥락 전달**
순서로 작업합니다. 원본 Figma 디자인과 별도의 해석을 저장합니다. 이미지가 있다는
것, 구조를 완전히 읽었다는 것, 사람이 승인했다는 것은 서로 다릅니다.

앱의 편집기는 자동 연결됩니다. 새 원본을 읽을 때는 같은 버전의 Figma 플러그인을
연결해 열어 두세요. Figma 없이도 **데모 불러오기**나 허용된 원본 파일로 작업할 수
있습니다. 언어 선택은 UI에만 적용되며, 원본 이름·원문·주석은 바뀌지 않습니다.

![원본 범위와 영역, 주석 도구가 보이는 합성 작업 공간](images/workflow.ko.png)

## 1. 필요한 원본 가져오기

**작업 공간**을 만들거나 엽니다. 가져오기나 작업 공간 전환 전에는 작성 중인 내용을
저장합니다. Figma에서 읽을 컨테이너 하나를 선택하고 앱의 **Figma 선택 영역 가져오기**를
누릅니다. 이름·경계를 확인한 뒤 **가져올 내용**을 고르고 **가져오기 시작**을 누르세요.

| 필요한 결과 | 선택 | 다음 단계 |
| --- | --- | --- |
| 작은 화면과 노드 | 미리보기 먼저, 원본 구조 나중 / 원본 구조 먼저, 미리보기 나중 | 필요한 두 단계가 끝나면 완료된 캡처 저장 |
| 먼저 영역을 그릴 이미지 | 미리보기만 | 미리보기로 초안 만들기 → 검토·승인 전에 일치하는 완전한 구조 연결 |
| 이미지 없이 원본 기록 | 작은 범위에서 원본 구조만 | 완료된 캡처 저장 → 문서 경계 안에서 영역 표시 |
| 선택한 큰 하위 트리 | 원본 구조 수집 | 작업 공간에 원본 구조 추가 / 현재 이미지 초안에 연결 |
| 특정 ID·바로 아래 자식·하위 분기 | 필요한 원본 노드 읽기 | 요청한 기록만 읽고 필요한 하위 영역 수집 |

이미지 초안에는 제안 상태의 영역을 저장할 수 있지만 매칭·승인할 원본 구조는 아직
없습니다. 완전한 수집은 이미지 없이도 원본 범위로 추가할 수 있습니다. 기존 이미지에
연결하려면 파일·페이지·루트·경계가 같아야 합니다. 비슷하게 보인다는 이유로 다른
분기의 수집을 연결하지 마세요.

[가져오기 가이드](acquisition-workflow.ko.md)에서 순서·한도·일시정지·재시도를
설명합니다. 이미지와 구조는 별도 시점의 관찰입니다. 가져오는 동안 원본 편집을
피하고 두 결과를 직접 비교하세요.

## 2. 의미 있는 영역을 그리고 저장

원본 범위를 선택하고 캔버스에 영역을 그리거나 **+ 영역 추가**를 누릅니다.
**구성요소 이름**, **역할**, 필요한 경우 **상위 구성요소**를 정하고 **주석 저장**을
누릅니다. 이 계층은 구현 의도를 나타내며 Figma 레이어 계층과 같을 필요가 없습니다.

좌표는 음수 위치도 포함하는 Figma 문서 좌표입니다. 이름·경계·노드 목록 변경은
저장 전 초안일 수 있습니다. 승인한 영역을 수정하면 다시 검토해야 합니다.
이름이 같다고 이전 승인이 새 내용에 그대로 적용되지는 않습니다.

## 3. 정확한 원본 노드 검토

**원본 연결 찾기**로 위치 기반 후보를 찾습니다. 겹치거나 모호한 후보를 확인하고,
후보 목록이나 원본 검색에서 의도한 노드를 골라 불필요한 참조를 제거하세요.
가장 높은 겹침 점수가 의미의 정답을 보장하지는 않습니다. 구조 수집의 목록은
페이지별로 읽고 원문은 선택할 때 불러옵니다. 캔버스에 불러온 경계 수와 전체
수집 노드 수는 다릅니다.

![후보 노드와 원본 확인 도구가 보이는 합성 원본 검토 화면](images/source-review.ko.png)

| 도구 | 용도 |
| --- | --- |
| Figma에서 보기 | 원본 노드를 선택하고 화면을 이동합니다. 디자인 속성은 변경하지 않습니다 |
| 현재 Figma 선택 추가 | 같은 원본 범위에서 명시적으로 선택한 노드 하나를 주석 초안에 추가합니다 |
| 현재 이미지 비교 | 현재 노드·하위 트리의 제한된 이미지를 요청해 비교합니다 |
| 비교 크게 보기 | 제공되는 화면에서 이미 받은 이미지를 확대합니다. Figma에 다시 요청하지 않습니다 |

현재 이미지 비교와 캡처 영역 미리보기는 작은 저장 캡처에서 제공합니다. 구조 수집을
연결한 영역에서는 노드 목록·원문과 Figma에서 보기를 사용하세요.

떨어진 분기의 노드도 같은 원본 범위에 속하면 하나씩 골라 같은 영역에 연결할 수
있습니다. 주석 하나에 서로 다른 범위의 노드를 섞을 수는 없습니다. 필요한 노드가
밖에 있다면 적절한 공통 컨테이너를 수집하거나 주석을 나누고 명세를 함께 연결하세요.

저장된 전체 캡처와 현재 노드 이미지는 관찰 시점이 다릅니다. 현재 노드 내보내기는
외부 형제를 제외하며 마스크·상위 가시성·겹침 등이 결과에 영향을 줄 수 있습니다.
빈 이미지의 원인을 이미지 하나로 단정하지 마세요. 숨겨졌거나 투명한 노드도 원본
기록으로 남으며, 자동 후보에서 빠졌더라도 직접 검토할 수 있습니다. 이를 보려고
원본 디자인을 수정하지 않습니다.

현재 노드 이미지는 1,024px·2MB·협력적 5초 예산으로 제한됩니다.
**현재 이미지 닫기**는 대기를 취소하지만 이미 실행된 Figma 렌더링은 끝날 수 있습니다.

## 4. 원본 확인과 의미 승인을 구분

1. 의도한 노드 집합으로 **주석 저장**을 누릅니다.
2. 저장된 집합을 검토하고 필요한 경우 **원본 확인**을 누릅니다. 수집에 연결된
   모든 주석에는 이 단계가 필요합니다. 작은 캡처도 모호하거나 숨겨진·알 수 없는
   원본이 포함되면 확인이 필요할 수 있습니다.
3. 이름·역할·경계·상위 관계의 의미를 검토하고 **주석 승인**을 누릅니다.
   해결되지 않은 내용은 제안 상태로 두거나 거절합니다.

원본 확인은 “이 노드들이 의도한 원본인가”, 의미 승인은 “이 해석이 구현에 적절한가”에
대한 판단입니다. 이미지를 보거나 AI 제안을 수락했다고 자동으로 확인·승인되지 않습니다.
경계나 참조가 바뀌면 다시 검토합니다. 하위 구성요소를 승인해도 의미상 상위가
미승인 상태라면 승인된 코딩 맥락에서 제외됩니다.

## 5. 명세 원문 연결

**명세**에서 실제 TEXT 기록을 선택합니다. 별도의 설명 영역에서 가져온 원문도
사용할 수 있습니다. 구조 수집에서는 텍스트 선택기를 열고 **원문 사용**을 누릅니다.
선택한 기록을 읽고 선택 순서대로 원문을 보존합니다.

**명세 만들기**로 원문을 확인하고 대상 구성요소와 동작·제약 등의 관계를 정한 뒤
**명세 저장**을 누릅니다. 대상 구성요소부터 승인하고, 검토를 마친 **명세 승인**으로
명세와 연결 관계를 승인합니다.

모든 UI 문구가 요구사항은 아닙니다. 근거 원문을 의역으로 대체하지 마세요.
픽셀 안의 글자, Figma 댓글과 네이티브 주석이 TEXT 기록으로 추출된다고 가정하지 않습니다.

## 6. 코딩 에이전트에 승인 맥락 전달

**JSON 내보내기**, **Markdown** 또는 [설치 가이드](alpha-installation.md)의 MCP를
사용합니다. `list_projects`로 시작해 해당 작업 공간의 `get_approved_context`,
`list_components`, `get_component`를 요청하세요. 앱은 켜 두되 저장된 자료를
읽는 데 Figma 연결은 필요하지 않습니다.

결과가 비어 있으면 구성요소·상위·명세 대상의 승인 상태를 확인합니다. 출력을 채우려고
승인하지 마세요. MCP는 제안을 만들 수 있지만 승인할 수 없습니다. Figma 안의
지시문도 원본 자료이며 코딩 에이전트가 따라야 하는 명령은 아닙니다.

## 원본 전달과 백업

| 목적 | 기능 | 전달 내용 |
| --- | --- | --- |
| 다른 곳에서 완전한 구조 수집 검토 | 원본 파일 → 원본 파일 내려받기 / 원본 파일 가져오기 | 구조 하나, 원문과 있으면 미리보기. 받는 작업 공간에 미검토 범위 추가 |
| 작은 캡처 1~2개 검토 | 캡처 전달 → 캡처 내보내기 / 캡처 가져오기 | 관찰 결과. 주석·승인 없이 새 작업 공간 생성 |
| 개발자에게 검토 결과 제공 | JSON 내보내기 / Markdown / MCP | 승인된 의미 구조·명세·출처 |
| 내 작업 복원 | 모든 쓰기 서비스를 중지하고 데이터 폴더 백업 | 자격 정보까지 포함한 전체 로컬 상태. 업데이트 가이드 참고 |

원본 파일은 최대 80MB NDJSON, 캡처 묶음은 최대 2개·합계 15MB JSON입니다.
두 전달 방식 모두 의미 승인을 전달하지 않으며 전체 작업 공간 백업도 아닙니다.
체크섬은 바이트 변경을 확인할 뿐 공유 권한이나 현재 Figma와의 일치를 증명하지 않습니다.
허용된 경로로만 전달하세요.

## 판단이 어려울 때

| 상황 | 다음 조치 |
| --- | --- |
| 이미지는 있지만 승인 불가 | 이미지 전용 초안인지 확인합니다. 일치하는 완전한 수집을 연결하고 노드를 저장·확인합니다 |
| 구조 미완료 | 한도·오류를 읽고 명시적으로 작은 범위나 구조 수집을 선택합니다. 일부 기록을 완료로 바꾸지 않습니다 |
| 수집 일시정지 | 유효한 같은 세션과 유휴 시간 안에서 재개합니다. 재연결·재시작은 진행 중 순회를 보존하지 않습니다 |
| 겹친 레이어·오래된 디자인처럼 보임 | 정확한 노드와 현재 이미지를 비교합니다. 위치·순서만으로 어느 디자인이 유효한지 판단하지 않습니다 |
| 원본 변경·다른 페이지 | 일치하는 원본을 열거나 새 범위를 가져와 재검토합니다. 식별자를 추측하지 않습니다 |
| Section·변형된 루트의 이미지 없음 | 구조와 경고를 보존하거나, 이미지를 위해 회전하지 않은 내부 Frame을 선택합니다 |
| 저장·승인 버튼 비활성 | 미저장 편집, 원본 확인, 진행 중 작업과 연결 상태를 확인합니다 |
| 리비전 충돌 | 편집 의도를 보존하고 새로고침한 최신 작업 공간에 적용합니다 |
| Figma·Dev Mode 접근 불가 | 허용된 전달 자료를 검토합니다. 새 읽기와 원본 이동은 접근이 확보될 때 진행합니다 |
| AI 생성 불가 | 수동 작업을 계속합니다. 기본 앱에는 제공자가 필요 없으며 외부 전송에는 별도 승인이 필요합니다 |

이 알파의 실제 Figma 검증은 제한된 합성 범위이며, 모든 큰 파일의 성능이나 사용자
생산성을 보장하지 않습니다. 다른 소유자의 보기 전용 파일과 Dev 전용 계정 조합은
별도 검증이 남아 있습니다. 설치·업데이트·데이터 보호는
[설치 가이드](alpha-installation.md)와 [업데이트·백업](upgrade-guide.md)을 참고하세요.
