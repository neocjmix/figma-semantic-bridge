# 상황별 작업 경로와 실패 후 선택지

> 이 문서는 **0.2.0의 보관된 분석**입니다. 0.2.1에서는 새 가져오기가 묶음 수집을 사용하고, 이미지·구조가 자동 저장·연결되며, 한도를 설정에서 조정합니다. 현재 사용법은 [가져오기·설정 안내](acquisition-workflow.ko.md)를 따르세요. 재연결 후 부분 자료 보충은 여전히 후속 작업입니다.

[English](user-scenarios.en.md) · [사용 가이드](user-guide.ko.md) · [가져오기 안내](acquisition-workflow.ko.md) · [개선 계획 제안](recovery-plan.ko.md)

**0.2.0 Alpha 기준 · 2026-10-26 확인**

현재 구현과 사용자 화면을 함께 확인한 분석입니다. 앞으로 만들 기능을 현재 가능한
기능에 포함하지 않았습니다. 여기서 ‘목적 완료’는 **필요한 원본을 확보하고, 사람이
원본과 의미를 검토·승인한 뒤 코딩 에이전트에 전달하는 것**입니다.
단순히 이미지를 보거나 일부 노드를 읽는 것과 구분합니다.

## 먼저 알아야 할 현재 상태

- 작은 범위는 이미지·노드를 가져와 검토·승인·전달까지 진행할 수 있습니다.
- 큰 범위도 **끝까지 수집되면** 같은 작업이 가능합니다. 이미지 없이도 가능합니다.
- 큰 수집의 **일시정지**는 조건이 맞으면 이어갑니다. **연결이 바뀐 뒤 복구**는
  다릅니다. 저장된 일부 자료가 있어도 그 지점부터 이어갈 수 없습니다.
- 특정 노드나 바로 아래 레이어만 읽고 다시 조회하는 기능은 있습니다. 그러나
  그 결과로 **실패한 전체 수집의 빈 부분을 채우는 기능은 없습니다.**
- 따라서 ‘자료가 남는다’는 안내가 ‘남은 자료로 원래 작업을 계속할 수 있다’는
  뜻은 아닙니다. 이 부분은 실제 제품의 미완성 지점입니다.

## 결과를 읽는 기준

| 표시 | 사용자에게 뜻하는 것 |
| --- | --- |
| 계속 가능 | 새로 가져오지 않고 다음 작업을 할 수 있음 |
| 같은 작업 재개 | 이미 저장한 부분을 유지하고 나머지를 읽을 수 있음. 조건 확인 필요 |
| 다시 시작 | 기존 기록은 남을 수 있지만 새 읽기는 처음부터 해야 함 |
| 범위를 바꾸면 가능 | 작은 영역 등으로 작업을 바꾸면 가능. 원래 전체 범위의 완료는 아님 |
| 현재 경로 막힘 | 지금 받은 자료와 현재 화면만으로 해당 목적을 끝낼 수 없음 |
| 외부 조건 필요 | 접근 권한, 허용된 원본, 백업 등 앱 밖의 조건이 필요함 |

‘막힘’은 해당 작업을 뜻합니다. 예를 들어 새 Figma 읽기가 막혀도 이전에 저장한
정상 자료는 검토할 수 있습니다. 저장 자료 자체가 손상된 경우는 별도입니다.

## 1. 앱을 열고 원본에 접근할 때

| 상황 | 성공 또는 실패 결과 | 지금 할 수 있는 일 | 원래 목적까지 가능한가 |
| --- | --- | --- | --- |
| 앱과 Figma 플러그인이 연결되고 읽을 영역 하나를 선택함 | 성공: 대상 이름과 경계를 확인하고 가져올 방법을 선택 | 작은 캡처, 이미지, 큰 구조 수집 또는 필요한 노드 읽기 | 가능. 다음 단계의 완성·검토가 필요 |
| Figma 플러그인이 닫혔거나 연결되지 않음 | 실패: 새 원본 읽기와 Figma에서 보기는 불가 | 플러그인 연결. 기존 정상 자료 검토·승인·전달, 허용된 원본 파일 가져오기는 가능 | 기존 자료로는 가능. 새 원본은 연결 복구 필요 |
| 앱의 로컬 서비스에 연결되지 않음 | 실패: 편집기·에이전트가 작업 공간을 읽고 저장할 수 없음 | 앱 실행과 연결 설정을 복구 | 연결 전에는 막힘. 새로고침만으로 저장되지 않은 입력이 복구되지는 않음 |
| 여러 영역을 선택했거나 읽을 수 없는 대상을 선택함 | 실패: 시작 전 거절 | 크기가 있는 Frame·Group 등 컨테이너 하나를 명시적으로 선택 | 다시 선택하면 가능 |
| 파일의 출처를 확인할 수 없음 | 실패: 출처가 필요한 새 읽기를 시작하지 못함 | 올바른 원본 파일과 로컬 플러그인 실행 경로 확인. 허용된 전달 자료 사용 | 외부 조건 필요. 출처를 임의로 입력해서 통과시키는 기능 없음 |
| 다른 소유자의 보기 전용 파일에서 플러그인을 실행하지 못함 | 새 읽기 불가 | 계정·파일·조직의 허용 조건 확인, 또는 허용된 방식으로 만든 원본 파일을 받아 검토 | 외부 조건 필요. 이 계정 조합의 실제 성공 검증은 아직 남음 |

Dev Mode를 결제했다는 사실만으로 모든 보기 전용 파일에서 이 앱이 동작한다고
확정할 수 없습니다. 반대로 현재 확인되지 않았다는 이유로 편집 권한이 반드시
필요하다고 결론 내릴 수도 없습니다. 원본을 수정하지 않는 것이 앱의 기본 동작입니다.

## 2. 작은 화면의 이미지와 노드를 가져올 때

**Figma 선택 영역 가져오기**의 네 선택지는 서로 다릅니다.

| 선택과 결과 | 저장된 자료로 할 수 있는 일 | 실패 시 다음 선택 | 판정 |
| --- | --- | --- | --- |
| 이미지와 구조 모두 성공 | **완료된 캡처 저장** 후 영역 표시·원본 검토·승인 | 별도 복구 불필요 | 계속 가능 |
| 처음부터 **원본 구조만** 골라 성공 | 이미지 없이 경계·노드·원문으로 검토·승인 | 이미지가 꼭 필요하면 별도 이미지 경로 선택 | 계속 가능 |
| 처음부터 **미리보기만** 골라 성공 | **미리보기로 초안 만들기**로 영역과 이름 저장 | 승인 전에는 같은 원본 영역의 완전한 구조를 수집해 연결 | 초안은 가능. 이 상태의 승인은 막힘 |
| 두 가지를 요청했는데 이미지 성공, 구조 실패·일부만 수신 | 받은 이미지를 보고 확대할 수 있음. 완료된 캡처 저장 불가 | 같은 연결에서 **원본 구조 처음부터 다시 읽기**, 또는 큰 구조 수집을 새로 시작 | 현재 화면에서 받은 이미지를 곧바로 영역 초안으로 바꾸는 버튼은 없음 |
| 두 가지를 요청했는데 구조 성공, 이미지 실패 | 구조 결과는 남지만 완료된 캡처 저장 불가 | 같은 연결에서 **미리보기 다시 시도**. 이미지가 필요 없다면 새 작업에서 구조만 다시 읽기 | 이미지 실패를 건너뛰어 기존 구조만 저장하는 버튼은 없음 |
| 구조가 노드 수·용량·시간 한도에 걸림 | 받은 일부 구조와 중단 사유는 기록에 남음. 편집기에 추가 불가 | 큰 구조 수집으로 전환하거나 필요한 범위를 명시적으로 줄임 | 같은 한도 재시도는 해결책이 아님. 받은 일부에 추가로 붙이기는 불가 |
| 사용자가 가져오기 중단을 누름 | 먼저 완료된 결과는 남음. 늦게 도착한 결과는 사용하지 않음 | 새 가져오기 시작 | 중단한 작업 자체를 재시도하는 버튼은 없음 |
| 읽는 중 앱이 종료되거나 Figma 연결이 바뀜 | 먼저 저장된 결과·기록은 남을 수 있음 | 완료 상태로 저장 가능한 결과는 저장. 끝나지 않은 읽기는 원본을 다시 확인해 새로 시작 | 중단 지점부터 재개 불가 |

작은 구조 읽기의 기본 한도는 **5,000개 노드·2MB·읽기 5초**입니다.
이 경로의 구조 재시도는 **처음부터** 읽습니다. 성공한 이미지까지 다시 요청하지는
않지만, 이미 받은 일부 구조를 이어 붙이지는 않습니다.

**‘미리보기 먼저, 원본 구조 나중’은 자동으로 그리는 작업 공간을 먼저 여는 기능이
아닙니다.** 이미지는 먼저 보여도, 구조 읽기가 진행 중인 같은 작업에서는 이미지
초안 만들기가 제공되지 않습니다. 먼저 영역을 그리고 싶다면 처음부터
**미리보기만 → 미리보기로 초안 만들기 → 별도 구조 수집** 순서를 사용합니다.
이미 두 단계 작업이 실패했다면 이 경로를 새로 시작할 때 이미지를 다시 읽게 됩니다.

## 3. 큰 영역의 전체 구조를 수집할 때

**원본 구조 수집**은 작은 캡처와 다른 경로입니다. 최대 20만 노드·64MB를,
한 번에 최대 500개·1MB씩 저장합니다. 이미지는 별도로 가져옵니다.

| 상황 | 남아 있는 자료와 사용 가능 범위 | 다음 조치 | 판정 |
| --- | --- | --- | --- |
| 전체 수집 완료 | 노드 목록·원문 조회, 작업 공간에 추가, 검토·승인·전달 가능 | 이미지가 없으면 그대로 검토하거나 일치하는 이미지 초안에 연결 | 계속 가능 |
| 사용자가 일시정지함 | 저장 완료한 부분과 진행 수치가 남음. 아직 노드 목록 조회·편집기 추가 불가 | 같은 유효한 연결에서 **수집 재개** | 같은 작업 재개 |
| 한 실행이 약 5분에 도달함 | 묶음 사이에서 자동 일시정지. 완료한 부분 유지 | 같은 조건에서 수집 재개 | 같은 작업 재개. 전체 작업을 5분 안에 끝내야 한다는 뜻은 아님 |
| 일시적으로 Figma가 바쁘거나 응답이 늦음 | 연결이 유지되면 일시정지 상태로 남음 | 원인을 확인하고 수집 재개. 저장 완료한 부분은 다시 읽지 않음 | 조건부 재개. 같은 응답을 다시 요청할 수도 있음 |
| 10분 동안 진행하지 않음, 플러그인 재연결, 앱 재시작 | 디스크에 저장한 부분과 기록은 남아도 이어 읽을 위치를 복구하지 못함 | 새 수집을 처음부터 시작하거나 필요한 작은 영역을 새로 수집 | 현재 중단 자료의 활용·보충 경로는 막힘 |
| 다른 페이지로 이동하거나 원본 변경이 감지됨 | 다른 시점·원본을 섞지 않도록 진행 거절 | 원본을 확인하고 새로 수집·검토 | 기존 부분에 새 결과를 덧붙일 수 없음 |
| 전체 노드·용량 한도 초과, 한 노드의 원문이 너무 큼 | 완전한 구조로 사용할 수 없음 | 필요 범위를 줄일 수 있으면 새로 수집 | 범위를 바꾸면 가능. 꼭 같은 전체 범위가 필요하면 현재 경로 막힘 |
| 중복·누락·부모 관계·저장 자료 검사 실패 | 완성된 자료로 인정하지 않음 | 원인 해결 후 새 수집 또는 정상 백업 복구 | 단순 재개로 해결된다고 보장할 수 없음 |
| 일시정지한 작업을 둔 채 다른 구조 수집 시작 | 이전 읽기가 자리를 사용 중이어서 새 수집이 막힐 수 있음 | 이전 작업 재개 또는 필요 없으면 기록 삭제. 삭제는 저장한 부분도 제거 | 해제 후 새 작업 가능. 재연결로 풀면 이전 재개 가능성은 잃음 |
| 삭제를 눌렀는데 Figma의 읽기 종료 확인 실패 | 기록을 보존하며 삭제 실패 | 종료 확인·삭제 재시도, 필요하면 플러그인 재연결 | 새 읽기까지 일시적으로 막힐 수 있음 |

일시정지는 현재 부분을 읽고 저장한 뒤 적용됩니다. 즉시 정지나 최대 메모리 사용량을
보장하지 않습니다. Figma 내부에서 매우 많은 자식 레이어를 한꺼번에 준비하는
작업은 앱이 응답을 작게 나눈다고 같은 크기로 제한되지 않습니다.

**핵심 구분:** 같은 연결 안에서의 재개는 있습니다. 연결이 바뀐 뒤 저장된 부분을
검토하거나, 빠진 부분만 다시 가져와 완성하는 복구는 없습니다.

## 4. 필요한 노드나 작은 하위 영역만 읽을 때

| 상황 | 할 수 있는 일 | 할 수 없는 일·복구 조건 | 판정 |
| --- | --- | --- | --- |
| 알고 있는 노드 ID로 읽기 성공 | 그 노드의 정보, 요청했다면 원문 확인. 같은 요청의 저장 결과 재사용 | 그 아래 모든 노드를 읽었다는 뜻 아님. 조사 결과를 바로 승인할 원본으로 연결 불가 | 조사 목적 완료. 검토·승인 목적은 추가 수집 필요 |
| 한 부모의 바로 아래 레이어 목록을 끝까지 읽음 | 직접 자식 목록 확인, 필요한 컨테이너 선택 | 손자 이하까지 읽은 것은 아님 | 탐색 목적 완료 |
| 목록을 읽다 응답이 끊겼지만 같은 연결이 유지됨 | 이미 저장된 목록 다시 보기, 같은 위치 재요청 | Figma의 읽기 위치가 아직 유효해야 다음 목록 수신 가능 | 조건부 재시도 |
| 목록을 읽다 재연결·앱 재시작 | 이전에 저장된 목록·원문은 조회 가능 | 다음 목록을 이어 읽으려면 새 조사가 필요. 과거 자료를 최신 결과로 자동 합치지 않음 | 조회는 계속 가능, 연속 읽기는 다시 시작 |
| 선택한 하위 영역을 끝까지 수집함 | **원본 구조 수집**의 기록에서 선택해 작업 공간에 추가·검토·승인 | 바깥 형제 영역은 포함하지 않음. 큰 이미지 초안에 작은 분기를 그대로 연결 불가 | 그 하위 영역의 목적은 완료 가능 |
| 중단된 큰 수집 뒤, 빠진 것으로 보이는 ID만 따로 읽음 | 별도 조사 결과로 확인 가능 | 중단된 큰 수집을 완성하지 못함. 이미 수집한 부분과 자동 통합·중복 제거·누락 판정 없음 | 원래 전체 목적은 여전히 막힘 |
| 같은 요청 결과를 다시 열었는데 원본이 이미 변경됨 | 이전 관찰을 다시 볼 수 있음 | 저장 결과 재사용은 최신성 확인이 아님. 새 조사를 시작해야 새 원본을 읽음 | 최신 자료가 필요하면 다시 시작 |
| 특정 노드가 없거나 선택한 범위 밖으로 이동함 | 오류 원인 확인 후 올바른 ID·범위를 새로 선택 | 없는 노드를 조용히 생략하고 성공 처리하지 않음 | 대상 수정 필요 |

앱의 ID 지정 읽기는 최대 100개씩, 바로 아래 목록은 최대 100개씩 읽습니다.
코딩 에이전트의 ID 지정 도구는 한 번에 최대 40개입니다. 모두 ‘전체 수집의
빈 부분을 채우기’와는 별개입니다.

## 5. 이미지와 원본 구조를 연결할 때

| 상황 | 결과와 다음 조치 | 목적 달성 여부 |
| --- | --- | --- |
| 이미지 초안과 완전한 구조가 같은 파일·페이지·선택 영역·경계임 | 이미지와 기존 영역 초안을 유지해 연결. 원본 노드를 저장·확인하고 의미 승인 | 가능. 이미지와 구조가 다른 시점이라는 점은 직접 확인 |
| 화면은 비슷하지만 파일·선택 영역·경계가 다름 | 연결 거절. 맞는 전체 영역을 수집하거나 별도 원본으로 추가 | 현재 초안에 그대로 연결은 막힘 |
| 큰 이미지에서 일부 영역만 수집 완료 | 작은 영역은 독립적으로 사용 가능 | 큰 이미지 전체의 미완료를 해결한 것은 아님 |
| 이미 연결한 구조를 새 구조로 바꾸고 싶음 | 새 원본 범위를 추가하고 다시 검토해야 함 | 기존 영역·승인을 새 자료로 자동 이전하는 기능 없음 |
| 새 이미지는 없지만 구조는 완전함 | 문서 좌표와 노드·원문으로 검토 가능 | 가능. 시각 판단이 필요한 부분은 Figma에서 직접 확인 |
| Section 또는 지원하지 않는 회전·변형 때문에 이미지 불가 | 구조만 수집하거나, 적절한 내부 Frame을 명시적으로 선택해 이미지를 가져옴 | 구조 목적은 가능. 다른 Frame을 고르면 읽는 범위도 달라짐 |

## 6. 겹친 레이어와 흩어진 노드를 검토할 때

| 상황 | 성공 경로 | 실패·판단 한계 | 막히는 범위 |
| --- | --- | --- | --- |
| 한 구성요소가 멀리 떨어진 여러 레이어에 걸쳐 있음 | 모두 같은 수집 영역에 있으면 여러 노드를 골라 하나의 영역에 연결 | 다른 원본 범위의 노드를 주석 하나에 섞을 수 없음 | 공통 영역을 새로 수집하거나 영역을 나눠 검토. 전체를 못 읽으면 원래 단일 영역 목적은 막힘 |
| 구버전이 숨김 또는 투명도 0으로 남음 | 해당 기록은 보존. 자동 위치 후보에서는 제외하고 필요하면 직접 선택·확인 | 숨김 여부만으로 구버전이라고 단정하지 않음 | 사람이 판단할 수 있으면 진행 가능 |
| 구버전이 투명하지 않고 신버전 뒤에 덮여 있음 | 정확한 노드를 선택해 Figma에서 확인하고 현재 이미지 비교 | 위치·순서·이미지만으로 실제 보이는 레이어나 최신 의도를 자동 확정 못함 | 사람도 판단 못하면 해당 의미 승인을 보류. 다른 영역은 진행 가능 |
| 현재 이미지 비교 성공 | 저장 이미지와 현재 노드 이미지를 참고해 원본 확인 | 이미지를 본 것만으로 승인되지 않음. 바깥 형제 레이어는 현재 노드 이미지에 안 나올 수 있음 | 검토 후 진행 가능 |
| 현재 이미지 비교 실패·빈 이미지 | Figma에서 보기, 저장 이미지·노드·원문으로 직접 검토. 원본 변경이면 새 수집 | 빈 이미지의 원인을 자동 확정 못함. 불확실한데 승인할 필요 없음 | 비교 기능만 실패할 수 있음. 판단 자료가 부족하면 해당 승인 보류 |
| 자동 후보가 너무 많거나 정답이 아님 | 전체 저장 자료에서 검색해 의도한 노드를 직접 선택하고 확인 | 위치 점수는 의미의 확률이 아님. 화면에 불러온 경계만으로 전체 누락 여부를 판단하면 안 됨 | 수동 검토로 가능할 수 있음 |

현재 이미지 비교는 **작은 저장 캡처와 완전한 구조 수집에 연결된 영역 모두**에
제공됩니다. 새 이미지를 읽으므로 Figma 연결이 필요합니다. 이미지 전용 초안은
아직 확인할 원본 노드가 없습니다. 원본 내용은 바꾸지 않으며, **Figma에서 보기**는
선택과 화면 위치를 이동합니다.

## 7. 저장·승인하고 명세를 연결할 때

| 상황 | 지금 할 수 있는 일 | 최종 승인·전달 |
| --- | --- | --- |
| 이미지 전용 초안 | 영역·이름을 제안 상태로 저장 | 일치하는 완전한 구조를 연결하기 전에는 불가 |
| 불완전한 작은 캡처가 이전 자료·파일로 이미 작업 공간에 있음 | 저장된 일부를 보고 제안 작업 가능 | 새 원본 매칭·확인·승인은 불가. 현재 가져오기 화면은 이런 미완료 캡처의 새 저장 자체를 막음 |
| 완전한 원본, 노드 선택·저장 완료 | 필요한 원본 확인 후 의미 승인 | 가능. 큰 구조 수집에 연결된 영역은 항상 원본 확인 필요 |
| 아직 저장하지 않은 입력이 있음 | 먼저 저장. 일부 가져오기·연결·확인 동작은 비활성 | 저장 후 계속. 앱 종료·새로고침으로 미저장 입력 보존은 보장 안 됨 |
| 다른 창·에이전트 작업으로 저장 내용이 바뀜 | 입력 의도를 따로 보존하고 최신 작업 공간을 불러와 다시 적용 | 충돌 해결 전 해당 저장은 막힘. 무조건 재시도로 덮어쓰지 않음 |
| 승인한 영역의 이름·경계·원본을 수정함 | 변경을 저장하고 다시 의미 검토 | 의미 승인은 다시 필요. 경계·원본 변경은 원본 확인도 다시 필요 |
| 명세 원문이 정상적인 TEXT 레이어에 있음 | 원문 그대로 선택하고 대상 영역과 관계를 저장. 대상부터 승인 | 검토한 대상과 명세 승인 후 전달 가능 |
| 글자가 이미지에만 있거나 댓글·별도 주석에 있음 | Figma에서 직접 확인 | 현재 자동 원문 추출 대상으로 볼 수 없음. 이미지 글자 인식이나 댓글 수집은 대안으로 구현되지 않음 |
| 원문 일부만 읽었거나 한 레이어의 원문이 저장 한도를 넘음 | 추가 원문 조회가 가능한 경우 끝까지 읽기. 한도 초과는 별도 문제로 보존 | 잘라낸 문장을 완전한 원문처럼 승인할 수 없음 |
| AI 제공자 없음·오류·제안 부정확 | 모든 수동 기능 계속 사용. 제안은 거절하거나 새로 요청 | AI는 필수 아님. 제안 수락만으로 의미 승인되지 않음 |
| 외부 AI로 원본을 보내는 데 동의하지 않음 | 외부 전송 없이 수동 검토 계속 | 수동으로 목적 완료 가능. 회사 자료 전송에는 해당 조직의 허용도 필요 |

여기서 완전한 원본은 **선택해 수집한 범위** 전체를 말합니다. 파일 전체를 수집해야
한다는 뜻도, 어떤 레이어가 실제 제품 의도인지 앱이 증명했다는 뜻도 아닙니다.

## 8. 전달·오프라인 작업·백업할 때

| 상황 | 가능한 경로 | 실패 후 선택·주의 |
| --- | --- | --- |
| 원본과 의미를 승인함 | JSON·Markdown 또는 코딩 에이전트로 승인 맥락 전달 | 승인되지 않은 의미상 상위가 있으면 하위도 전달 대상에서 빠짐. 상위 관계와 승인 상태 확인 |
| 전달 결과가 비거나 일부만 나옴 | 승인 상태, 명세 대상, 출력의 누락·분량 안내 확인 | 승인할 내용이 없으면 빈 결과가 정상. 에이전트는 나눠 조회 가능. 작게 받은 결과를 전체라고 간주하지 않음 |
| Figma 연결 없이 저장 작업 계속 | 정상적으로 저장된 완전한 원본으로 검토·승인·전달 | 새 원본·현재 이미지 읽기와 Figma에서 보기는 연결 필요 |
| 다른 사람이 정상 원본 파일을 전달함 | **원본 파일 가져오기**로 현재 작업 공간에 미검토 원본 추가 | 최대 80MB의 앱 전용 원본 파일. 임의의 Figma 파일이나 PNG를 대신 넣을 수 없음 |
| 작은 캡처 묶음을 전달받음 | 별도 새 작업 공간에서 검토 | 원본·이미지 관찰만 전달. 주석·명세·승인은 따라오지 않음 |
| 원본 파일이 잘렸거나 손상됨 | 가져오기 거절. 정상 파일 재전달 요청 | 빠진 부분만 추가 업로드해 이전 실패를 완성하는 기능 없음 |
| 저장 공간 부족·수집 기록 수 한도 | 필요 없는 기록 정리, 디스크 공간 확보 후 다시 시도 | 사용 중인 원본 구조는 삭제 불가. 기록 삭제는 백업이 아니며 미완료 자료도 지워짐 |
| 작업 공간이 사용하는 원본 자료가 사라지거나 손상됨 | 전체 자료를 포함한 정상 백업 복구 | 새 승인·전달이 막히고 다른 저장도 영향받을 수 있음. 새로 수집한 다른 자료를 자동 대체 연결하지 못함 |
| 앱을 켤 때 저장된 수집 자료 검사부터 실패함 | 정상 백업 복구와 원인 점검 필요 | 로컬 서비스가 시작하지 못해 편집기 전체가 막힐 수 있음. 자료를 무작정 삭제해 해결할 상황으로 보지 않음 |
| 앱 업데이트 또는 기기 이동 | 모든 쓰기 서비스를 종료하고 전체 데이터 폴더 백업·복원 | 승인 JSON과 원본 전달 파일은 전체 작업 공간 복구용 백업이 아님 |

원본 파일과 작은 캡처 묶음은 **검토·승인 기록을 전달하지 않습니다.** 승인 결과
내보내기는 사람이 검토한 구현 맥락을 전달하는 기능이지 전체 원본 보관·복구 기능이
아닙니다. 원본 공유는 소유자와 조직이 허용한 범위에서 진행합니다.

## 9. 지금 중단된 수집이 있다면

1. **큰 구조 수집이 ‘일시정지’이고 연결을 유지했는가?** 그렇다면 원본을 편집하거나
   페이지를 바꾸지 말고 재개합니다. 유휴 10분을 넘기지 않아야 합니다.
2. **연결이 바뀌었거나 앱을 다시 실행했는가?** 기존 일부를 이어서 완성할 수 없습니다.
   원래 전체 영역이 꼭 필요하면 처음부터 새 수집이 필요합니다.
3. **작은 캡처가 한도에 걸렸는가?** 같은 버튼 반복보다 큰 구조 수집으로 새로 시작합니다.
   이전 일부를 자동 이전하지는 않습니다.
4. **작은 하위 영역으로 실제 목적을 충족할 수 있는가?** 그렇다면 그 영역을 새로
   수집해 끝까지 검토합니다. 다른 영역까지 처리했다고 보고하지 않습니다.
5. **이미지와 몇 개 노드만 남았는가?** 이미지 보기·별도 조사 결과 확인은 가능할 수
   있지만, 이를 합쳐 승인 가능한 원본으로 만드는 작업은 현재 막혀 있습니다.

현재 앱은 실패하면 Figma REST API로 자동 전환하지 않습니다. 이미지 렌더링과
구조 읽기도 사용자가 고른 순서대로 실행하며, 동시에 실행해 문제를 해결하는
기능은 없습니다. 시작한 Figma 이미지 렌더링을 즉시 중단할 수는 없으므로 중단 후
잠시 바쁠 수 있습니다. 이런 경우 새 요청을 연속해서 보내기보다 종료를 확인합니다.

## 10. 구현되어야 해소되는 막힘

다음은 사용자가 설정을 잘못해서 생기는 문제가 아니라 **현재 없는 기능**입니다.

| 필요한 기능 | 해결할 사용자 문제 |
| --- | --- |
| 중단된 자료 열기와 사용 범위 표시 | 저장된 부분조차 검토·활용하지 못하는 문제 |
| 받은 부분·아직 없는 부분 구분, 필요한 부분만 보충 | 연결이 끊기면 처음부터 다시 읽는 비용과 누락 불확실성 |
| 여러 번 읽은 자료를 검증해 통합 | 특정 노드 조회가 전체 수집 보충으로 이어지지 않는 문제. 서로 다른 시점·범위를 함부로 섞지 않는 검증 필요 |
| 두 단계 가져오기 실패 후 성공한 자료만 사용 | 이미지가 있어도 초안 생성 불가, 구조가 있어도 이미지 실패 때문에 저장 불가한 문제 |
| 작은 범위로 나눈 뒤 원래 작업과의 관계 관리 | 작은 영역 성공을 전체 작업 완료로 오인하는 문제와 초안 재작성 비용 |

이 기능들을 추가할 때도 **받지 않은 자료를 없는 것으로 취급하거나, 미완료 원본을
완료로 표시해서 승인 제한만 푸는 방식은 해결책이 아닙니다.**
