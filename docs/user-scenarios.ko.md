# 상황별 작업과 복구 안내

[English](user-scenarios.en.md) · [사용 가이드](user-guide.ko.md) · [가져오기·설정](acquisition-workflow.ko.md)

기본 순서는 **원본 추가 → 영역 저장 → 원본 확인·영역 승인 → 명세 연결 → 공유**입니다.
아래에서 현재 상태와 다음 행동을 찾으세요. “진행 범위”는 해당 문제 중에도 할 수 있는 작업입니다.

## 정상적으로 진행할 때

| 현재 상태 | 다음 행동 | 결과 |
| --- | --- | --- |
| 앱을 처음 열었음 | 작업 공간을 만들고 Figma 플러그인 연결 | 선택한 Frame을 가져올 준비 |
| Figma Frame을 선택함 | **원본 추가 → 가져오기 시작** | 이미지와 원본 자료를 로컬에 저장 |
| 이미지가 먼저 나타남 | 영역을 그리고 이름 입력 → **영역 저장** | 구조를 기다리는 동안 초안 작성 |
| 구조가 준비됨 | 저장된 영역의 연결 노드 확인 | 원본과 영역의 관계 검토 |
| 연결 노드가 맞음 | **원본 확인 → 영역 승인** | 구현에 전달할 영역 준비 |
| 승인한 영역에 요구사항이 있음 | **명세 연결 → 원문 선택 → 명세 만들기** | 해당 영역을 대상으로 명세 초안 작성 |
| 원문과 연결 대상이 맞음 | **명세 저장 → 명세 승인** | 요구사항과 영역의 관계 확정 |
| 검토를 마침 | **전달하기 → JSON 내보내기 / Markdown**, 또는 MCP | 승인된 내용 전달 |

## 연결과 가져오기

| 상황 | 진행 범위 | 복구 방법 |
| --- | --- | --- |
| Figma 연결 전 | 저장된 자료·승인 결과 사용 가능 | Figma 플러그인을 열고 앱의 연결 토큰으로 연결 |
| 원본을 선택하지 않았거나 여러 개 선택함 | 기존 작업 계속 가능 | 작업할 Frame 하나를 선택하고 **원본 추가** |
| 준비 후 파일·페이지·선택이 바뀜 | 기존 작업과 받은 자료 유지 | 의도한 원본으로 돌아가 다시 준비 |
| 노드·용량·읽기 시간 한도에 도달함 | 받은 자료 조회, 준비된 부분 검토 가능 | 필요한 한도를 **설정**에서 늘리고 **계속** |
| Figma가 바쁘거나 응답이 늦음 | 받은 자료와 기존 작업 유지 | Figma 상태를 확인하고 **계속** |
| 앱 재시작·플러그인 재연결 | 저장된 자료와 승인을 그대로 사용 | **계속**에서 재확인 작업을 확인한 뒤 진행 |
| 이미지 실패, 구조 성공 | 노드·원문으로 영역 작성과 검토 가능 | 필요한 모습은 Figma에서 확인하거나 적절한 내부 Frame을 새로 가져오기 |
| 이미지 성공, 구조 중단 | 이미지 초안·받은 노드·완료된 부분 사용 가능 | **계속**, **이 부분 검토**, **이 부분 준비** 중 현재 필요한 작업 진행 |
| 필요한 작은 부분만 아직 덜 읽힘 | 다른 준비된 부분은 계속 사용 | **받은 원본 자료 → 이 부분 준비** |
| 원본 삭제·접근 권한 변경 | 기존 저장 자료 조회 가능 | 접근 가능한 원본으로 돌아가거나 새 원본 추가 |
| 저장 공간 부족 | 이미 저장한 자료 유지 | 공간 확보 후 **계속**. 원본 데이터 폴더를 임의로 지우지 않기 |
| 저장된 자료 손상 | 손상 자료에 의존하지 않는 작업 가능 | 정상 백업 복원 또는 새 원본 추가 후 재검토 |

같은 연결에서는 읽던 위치에서 이어갑니다. 재연결 후에는 저장한 부분도 원본에서 다시
확인합니다. 기존 승인과 자료는 유지되며 새 관찰은 별도로 저장됩니다.
Figma의 이미지 내보내기는 요청 취소 직후에도 마무리 중일 수 있습니다.

## 영역과 원본 검토

| 상황 | 진행 범위 | 복구 방법 |
| --- | --- | --- |
| 이미지 초안만 준비됨 | 영역 이름·경계 저장 가능 | 구조 준비 후 원본 확인과 승인 |
| 연결 노드가 비어 있음 | 영역 초안 유지 | 원본 후보를 다시 찾거나 검색·Figma 선택으로 노드 추가 → 저장 |
| 서로 떨어진 분기의 노드가 하나의 구성요소임 | 같은 원본 범위 안에서 함께 연결 가능 | 의도한 노드를 하나씩 추가 → 저장 → 확인 |
| 다른 원본 범위의 노드까지 필요함 | 별도 영역으로 작업 가능 | 공통 Frame을 가져오거나 영역을 나눠 같은 명세 연결 |
| 예전 레이어가 투명하거나 다른 레이어에 가려짐 | 저장 자료와 후보 비교 가능 | **Figma에서 보기**, **현재 이미지 비교**로 의도한 노드를 선택 |
| 부분 검토 영역이 준비된 범위 밖까지 걸침 | 영역 초안 유지 | 실제 필요한 경계를 조정하거나 더 넓은 원본 준비 |
| 승인한 영역을 수정함 | 기존 자료 유지, 수정본 재검토 가능 | 저장 후 필요한 원본 확인과 영역 승인 |
| 상위 영역이 아직 승인 전임 | 하위 영역 편집·검토 가능 | 상위를 승인하면 공유 결과에 계층 포함 |
| 분할·병합 결과가 의도와 다름 | 이전 편집 복원 가능 | **실행 취소**, 필요하면 **다시 실행** |
| 하위 영역이 있어 삭제·분할이 막힘 | 기존 영역 그대로 유지 | 하위 영역의 상위를 바꾸거나 하위부터 정리한 뒤 재시도 |
| 저장 오류가 발생함 | 현재 초안 유지 | 입력·선택한 원본을 수정해 다시 저장. 반복되면 진단 번호 확인 |

겹친 정도나 레이어 순서는 의미를 판단하는 참고 자료입니다. 최종 원본 선택과 승인은
사람이 결정합니다. 부분 승인은 전체 가져오기의 완료를 뜻하지 않습니다.

## 명세·공유·기타 편집

| 상황 | 진행 범위 | 복구 방법 |
| --- | --- | --- |
| 명세 원문이 별도 Frame에 있음 | 현재 영역 작업 유지 | 같은 작업 공간에 해당 Frame을 추가하고 **명세 원본**에서 선택 |
| 선택할 텍스트가 없음 | 영역 검토·공유 가능 | TEXT가 포함된 원본을 준비. 이미지 속 글자·댓글은 별도 확인 |
| 원문 로딩이 실패함 | 저장한 명세와 다른 작업 유지 | 같은 원문을 다시 선택. 자료 손상이면 정상 원본 복구 |
| 명세 대상이 아직 승인 전임 | 명세 초안 저장 가능 | 연결된 영역을 승인한 뒤 명세 승인 |
| 미저장 편집 때문에 다른 작업을 선택할 수 없음 | 현재 초안 편집 가능 | 저장하거나 변경 버리기 후 이동 |
| 다른 창·에이전트가 작업 공간을 갱신함 | 저장한 자료 유지 | 초안 내용을 확보하고 새로고침한 최신 내용에 다시 적용 |
| 공유 결과에 일부 항목이 빠짐 | 포함 가능한 승인 결과 전달 가능 | 영역·상위·명세 대상의 승인 상태 확인 |
| 원본 파일 가져오기가 실패함 | 기존 작업 공간 유지 | 올바른 파일을 다시 선택. 손상된 파일은 다시 내려받기 |
| 설정이 저장되지 않음 | 이전 설정으로 계속 사용 가능 | 표시된 범위 안으로 수정. 충돌 시 설정을 다시 열어 저장 |
| AI 제안 생성이 안 됨 | 수동 작업·검토 계속 가능 | 지원되는 원본과 모델 설정 확인. 수동 작업으로 동일한 결과 작성 가능 |
| 오래된 제안을 적용할 수 없음 | 최신 사람 편집 유지 | 제안을 거절하고 최신 원본으로 다시 작성 |

실행 취소·다시 실행은 최근 저장된 편집을 복원합니다. 앱 종료 전의 미저장 입력이나
전체 자료를 복구하는 백업의 역할은 하지 않습니다. 전체 복구는
[업데이트·백업 안내](upgrade-guide.md)를 따르세요.

## 오류를 확인할 때

오류가 반복되면 **실행한 동작, 발생 시각, 화면의 진단 번호**를 기록하세요.
로컬 진단 기록은 요청과 결과를 연결해 원인을 조사하는 데 사용됩니다. 자세한 검증 범위는
[온라인 QA 기록](https://github.com/neocjmix/figma-semantic-bridge/blob/main/docs/evaluation/guided-workflow-qa.md)에 정리합니다.
원본 이미지·원문·연결 토큰을 오류 신고에 첨부할 필요는 없습니다.

현재 알파에서 다른 소유자의 보기 전용 파일과 Dev 전용 계정 조합, 모든 큰 업무 파일의
성능은 각 실제 환경에서 추가 확인이 필요합니다. 이 조건은 저장된 자료를 검토하는 기능과
구분됩니다.
