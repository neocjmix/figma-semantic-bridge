# 상황별 작업과 복구

[English](user-scenarios.en.md) · [사용 가이드](user-guide.ko.md) · [가져오기·설정](acquisition-workflow.ko.md)

이 앱은 Figma 원본을 가져와 사람이 영역과 의미를 정리하고 승인하는 도구입니다.
**이미지 수신, 원본 구조 준비, 사람의 승인은 서로 다른 단계**입니다.
아래는 0.3.0 Alpha의 사용자 흐름입니다.

## 정상적으로 진행되는 경우

| 상황 | 가능한 작업 | 다음 행동 |
| --- | --- | --- |
| 처음 원본 추가 | 대상·한도·위험 확인 | 가져오기 시작 |
| 이미지를 먼저 받음 | 확대, 영역 그리기, 이름·역할 저장 | 필요한 영역 정리 |
| 구조 수집 중 | 받은 노드·원문 조회, 제안 편집 | 기다리거나 일시정지 |
| 구조 전체 준비 완료 | 이미지가 없어도 원본 검색·매칭·검토 | 정확한 노드 확인 |
| 전체는 미완료지만 일부 하위 영역 준비 완료 | 그 부분만 큰 이미지 위에서 검토. 선택한 저장 제안 영역은 복사 | 이 부분 검토 |
| 필요한 컨테이너가 아직 미완료 | 그 컨테이너 아래만 읽기 | 이 부분 준비 |
| 정확한 원본을 확인함 | 이름·역할·관계의 의미 검토 | 주석 승인 |
| 주석·명세 승인 완료 | 승인 결과를 MCP나 파일로 전달 | 필요한 결과 전달 |

작은 부분을 승인해도 원래 전체 요청은 완료되지 않습니다. 부분 밖의 관련 레이어가
필요한 경우 더 넓은 원본을 확보해야 합니다. 그림이 겹쳐 보인다는 이유만으로
구버전·신버전이나 실제 보이는 레이어를 자동 확정하지 않습니다.

## 수집이 중단되거나 실패한 경우

| 상황 | 이미 받은 자료 | 복구 방법 | 무엇이 막히는가 |
| --- | --- | --- | --- |
| 노드·용량·실행 시간 한도 도달 | 저장된 이미지·묶음 유지 | 설정을 높이고 계속 | 준비되지 않은 범위의 승인만 제한 |
| 같은 유효한 연결에서 일시정지 | 저장된 위치까지 사용 가능 | 계속하면 다음 위치부터 읽기 | 현재 준비되지 않은 범위 |
| 일시적인 지연·Figma 사용 중 | 완료된 묶음 유지 | 원인 해소 후 계속 | 새 읽기만 일시 제한 |
| 앱 재시작·플러그인 재연결 | 저장 자료와 편집·승인 유지 | 계속에서 재확인 비용을 확인하고 진행 | 현재 Figma를 다시 읽는 동안 미확인 범위 |
| 전체 대신 필요한 부분부터 작업 | 원래 자료 유지 | 해당 부분 준비. 읽기 위치 해제가 필요하면 먼저 확인 | 전체 요청은 미완료 유지 |
| 이미지 실패, 구조 성공 | 원본 목록·원문 사용 가능 | 구조로 검토하거나 Figma에서 원본 비교 | 이미지가 꼭 필요한 시각 판단 |
| 이미지 성공, 구조 중단 | 이미지 초안·저장된 노드·완료된 부분 사용 가능 | 계속 또는 필요한 부분 준비 | 아직 충분한 원본이 없는 영역의 확인·승인 |
| 원문·자식·순서가 변경됨 | 과거 자료·승인 보존 | 새 관찰을 따로 검토 | 옛 승인을 새 원본에 자동 적용하지 않음 |
| 원본 삭제·접근 불가·다른 페이지 | 저장 자료는 계속 조회 가능 | 허용된 원본으로 돌아가거나 새 원본 추가 | 해당 원본의 새 읽기 |
| 디스크 부족·기록 용량 한도 | 이미 정상 저장한 자료 유지 | 공간 확보·불필요 기록 정리 후 계속 | 새 저장 |
| 저장 자료 손상 | 손상되지 않은 별도 작업은 보존 | 유효한 백업 복원 또는 원본 새로 수집 | 손상된 자료에 의존하는 검토·전달 |

**계속**은 사라진 Figma 읽기 위치를 복원하는 기능이 아닙니다. 재연결 뒤에는 이전에
받은 노드도 다시 확인합니다. 내용이 같으면 짧은 확인 응답으로 반복 전송을 줄입니다.
옛 자료와 새 자료를 확인 없이 섞어 전체 완료로 만들지 않습니다.

이미지 내보내기는 Figma 내부에서 진행되므로 즉시 취소되지 않을 수 있습니다.
일시정지는 현재 내보내기나 저장 중인 묶음이 끝난 뒤 반영됩니다. 같은 큰 렌더링을
반복 시작하거나 대기 시간만 높인다고 성공을 보장할 수는 없습니다.

## 검토·승인에서 막히는 경우

| 상황 | 이유와 다음 행동 |
| --- | --- |
| 이미지밖에 없음 | 영역 초안은 저장할 수 있습니다. 구조 또는 완전한 하위 영역을 준비하세요 |
| 부분 원본보다 큰 영역 | 그 범위 밖을 읽지 않았습니다. 충분히 넓은 원본을 준비하거나 작업할 영역을 명시적으로 조정하세요 |
| 후보가 여러 개·구버전이 겹침 | 후보와 원문을 비교하고 Figma에서 위치 확인·개별 미리보기를 사용한 뒤 정확한 원본을 선택하세요 |
| 숨김·투명한 상위 레이어가 있음 | 알려진 숨김 정보는 유지하고 자동 후보에서 제외합니다. 수동 선택은 실제 디자인과 비교해 명시적으로 확인해야 합니다 |
| 원본 연결이 없음 | 받은 원본에서 정확한 노드를 선택하세요. 관련 노드가 아직 없으면 해당 범위를 준비하세요 |
| 미저장 편집이 있음 | 저장하거나 취소한 뒤 다른 작업 공간·원본으로 이동하세요 |
| 이전 승인이 있지만 원본을 새로 읽음 | 옛 승인은 옛 근거에 남습니다. 새 관찰을 따로 검토하세요 |

## 파일·외부 연동

- 저장 자료 조회와 전달받은 원본 검토에는 Figma 연결이 필요하지 않습니다.
- 원본 파일에는 디자인 이미지와 원문이 포함될 수 있습니다. 공유 권한을 확인하세요.
  작은 부분을 내보내도 참고 이미지에는 주변 디자인이 포함될 수 있습니다.
  파일을 가져왔다고 주석·명세가 승인되지는 않습니다.
- 승인 결과 전달에는 승인된 근거만 포함됩니다. 원본 파일 전달과 전체 작업 백업은
  서로 다른 목적입니다.
- 선택한 영역 안에서도 여러 차례의 읽기는 고정된 한 시점의 원본을 보장하지 않습니다.
  그것이 필수인 업무라면 현재 경로만으로 충족했다고 볼 수 없습니다.
- 다른 소유자의 보기 전용 파일·조직 정책·원래 초대형 업무 파일의 실제 실행은
  해당 접근 환경에서 별도 확인해야 합니다. 저장 자료 기능과는 별개의 조건입니다.
